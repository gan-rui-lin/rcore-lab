# LTP 日志计分规则与脚本速查

本文记录工作区内和相邻 `autotest-for-oskernel` 仓库里的计分脚本用法，重点用于把 QEMU 原始日志里的 LTP 结果转成表格分数。

## 直接可用脚本

推荐直接使用：

```bash
python3 docs/HWTDocs/ltp_official_score.py docs/HWTDocs/rvlogs/allrv_full_0605_122616.log
```

这个脚本的分数口径和官方一致：它只负责按 `ltp-musl`/`ltp-glibc` 截段，然后调用相邻仓库里的官方 `judge_ltp-musl.py`/`judge_ltp-glibc.py`，最后把官方 JSON 做表格汇总。

| 需求 | 命令 |
|---|---|
| 自动计算日志中所有 LTP 段 | `python3 docs/HWTDocs/ltp_official_score.py path/to/log` |
| 只算完整跑完的 LTP 段 | `python3 docs/HWTDocs/ltp_official_score.py path/to/log --complete-only` |
| 只算 musl LTP | `python3 docs/HWTDocs/ltp_official_score.py path/to/log --suite ltp-musl` |
| 只算 glibc LTP | `python3 docs/HWTDocs/ltp_official_score.py path/to/log --suite ltp-glibc` |
| 多个日志合并出表 | `python3 docs/HWTDocs/ltp_official_score.py path/to/rv.log path/to/la.log` |
| 输出 JSON | `python3 docs/HWTDocs/ltp_official_score.py path/to/log --format json` |
| 输出 CSV | `python3 docs/HWTDocs/ltp_official_score.py path/to/log --format csv` |
| 指定官方 judge 目录 | `python3 docs/HWTDocs/ltp_official_score.py path/to/log --judge-dir ../autotest-for-oskernel/kernel/judge` |

## 结论速查

| 项目 | 推荐做法 | 说明 |
|---|---|---|
| 直接可用脚本 | `docs/HWTDocs/ltp_official_score.py` | 自动截段、调用官方 judge、输出 Markdown/JSON/CSV 表格。 |
| 官方 LTP 计分入口 | `../autotest-for-oskernel/kernel/judge/judge_ltp-musl.py`、`judge_ltp-glibc.py` | 输出 JSON 数组，字段为 `name/pass/all/score`；脚本内部直接调用它们。 |
| 本地汇总入口 | `tools/ltp_score_aggregate.py` | 把官方 judge 的 JSON 汇总成总分、得分率、满分/部分/零分 case 数。 |
| 原始日志分段 | 先按 `#### OS COMP TEST GROUP START/END ltp-* ####` 截出单个套件 | 不分段会被后续同名 case 覆盖或混入半截 glibc/musl。 |
| `FAIL LTP CASE xxx : 0` | 不代表失败 | 这是外层 runner 的结束行；真实结果看 `Summary`、`TPASS/TFAIL/TBROK/TCONF`、timeout 和非 0 返回码。 |
| `scripts/ltp/ltp-analyze.py` | 适合排障、排序、找高分 case | 不是最终计分口径；在带 Summary 的日志上可能把逐行 TPASS 和 Summary 合并得偏高。 |

## LTP 计分字段

| 字段 | 来源 | 含义 | 汇总方式 |
|---|---|---|---|
| `name` | judge 输出 | LTP case 名，如 `access01` | 不汇总 |
| `pass` | judge 输出 | 该 case 通过的子断言数 | `total_pass = sum(pass)` |
| `all` | judge 输出 | 该 case 有统计的子断言/状态总数 | `total_all = sum(all)` |
| `score` | judge 输出 | 当前官方脚本中等于 `pass` | `total_score = sum(score)` |
| `pass_rate` | 本地聚合 | `total_pass / total_all` | `total_all == 0` 时为 0 |
| `score_rate` | 本地聚合 | `total_score / total_all` | 当前等同于 `pass_rate` |
| `full_pass_cases` | 本地聚合 | `all > 0` 且 `pass == all` 的 case 数 | 计数 |
| `partial_pass_cases` | 本地聚合 | `0 < pass < all` 的 case 数 | 计数 |
| `zero_score_cases` | 本地聚合 | `all > 0` 且 `pass == 0` 的 case 数 | 计数 |
| `no_stat_cases` | 本地聚合 | `all == 0` 的 case 数 | 计数 |

## 脚本清单

| 脚本 | 输入 | 输出 | 用途 | 注意点 |
|---|---|---|---|---|
| `../autotest-for-oskernel/kernel/judge/judge_ltp-musl.py` | QEMU 原始日志或截出的 `ltp-musl` 段 | JSON 数组 | 官方 musl LTP 判分 | 主要读 `Summary`；建议先 `tr -d '\r'`。 |
| `../autotest-for-oskernel/kernel/judge/judge_ltp-glibc.py` | QEMU 原始日志或截出的 `ltp-glibc` 段 | JSON 数组 | 官方 glibc LTP 判分 | 主要匹配 ANSI 彩色 `TPASS/TFAIL/...` 标记。 |
| `tools/ltp_score_aggregate.py` | judge JSON 数组 | 文本或 JSON 汇总 | 汇总 LTP 总分和分布 | 不解析原始日志，只吃 `name/pass/all/score`。 |
| `scripts/ltp/ltp-analyze.py` | 原始 LTP 日志 | 表格、CSV、JSON | 排障和高分 case 排序 | 可识别 ANSI/非 ANSI，但不建议作为最终计分。 |
| `scripts/analyze_ltp_html.py` | HTML 报告 | 文本分析报告 | RV/LA、glibc/musl 横向对比 | 面向已有 HTML 报告，不是原始 QEMU 日志计分。 |

## 推荐命令

下面命令默认在仓库根目录执行。

| 场景 | 用法 |
|---|---|
| 计算完整 `ltp-musl` 段 | 用官方 musl judge 加本地聚合脚本 |
| 计算完整 `ltp-glibc` 段 | 用官方 glibc judge 加本地聚合脚本 |
| 输出 JSON 汇总 | 在 `tools/ltp_score_aggregate.py` 后加 `--json` |
| 排障和排序 | 用 `scripts/ltp/ltp-analyze.py` |
| 检查套件完整性 | 搜 `OS COMP TEST GROUP START/END ltp` |

计算完整 `ltp-musl` 段：

```bash
LOG=docs/HWTDocs/rvlogs/allrv_full_0605_122616.log
JUDGE=../autotest-for-oskernel/kernel/judge

awk '/#### OS COMP TEST GROUP START ltp-musl ####/{flag=1} flag{print} /#### OS COMP TEST GROUP END ltp-musl ####/{flag=0}' "$LOG" \
  | tr -d '\r' \
  | python3 "$JUDGE/judge_ltp-musl.py" \
  | python3 tools/ltp_score_aggregate.py
```

计算完整 `ltp-glibc` 段：

```bash
LOG=your.log
JUDGE=../autotest-for-oskernel/kernel/judge

awk '/#### OS COMP TEST GROUP START ltp-glibc ####/{flag=1} flag{print} /#### OS COMP TEST GROUP END ltp-glibc ####/{flag=0}' "$LOG" \
  | tr -d '\r' \
  | python3 "$JUDGE/judge_ltp-glibc.py" \
  | python3 tools/ltp_score_aggregate.py
```

其他常用命令：

```bash
python3 tools/ltp_score_aggregate.py --json
python3 scripts/ltp/ltp-analyze.py path/to/ltp.log --top 40
python3 scripts/ltp/ltp-analyze.py path/to/ltp.log --csv
rg -n "OS COMP TEST GROUP START ltp|OS COMP TEST GROUP END ltp" path/to/log
```

## 表格输出模板

如果要把聚合 JSON 直接变成 Markdown 表格，可以在官方 judge 后接这个小段：

```bash
python3 tools/ltp_score_aggregate.py --json | python3 -c '
import json, sys
s = json.load(sys.stdin)
print("| case数 | pass总和 | all总和 | score总和 | 得分率 | 满分case | 部分case | 0分case | 无统计case |")
print("|---:|---:|---:|---:|---:|---:|---:|---:|---:|")
print(f"| {s['total_cases']} | {s['total_pass']} | {s['total_all']} | {s['total_score']} | {s['score_rate']:.2%} | {s['full_pass_cases']} | {s['partial_pass_cases']} | {s['zero_score_cases']} | {s['no_stat_cases']} |")
'
```

输出表头如下：

| case数 | pass总和 | all总和 | score总和 | 得分率 | 满分case | 部分case | 0分case | 无统计case |
|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| `total_cases` | `total_pass` | `total_all` | `total_score` | `score_rate` | `full_pass_cases` | `partial_pass_cases` | `zero_score_cases` | `no_stat_cases` |

## 常见误判

| 现象 | 正确理解 | 处理 |
|---|---|---|
| `FAIL LTP CASE abort01 : 0` | 外层 runner 用 `FAIL` 表示 case 结束，返回码 0 通常说明 runner 没报错 | 看该 case 的 `Summary` 或 `TPASS/TFAIL/TBROK`。 |
| `FAIL LTP CASE xxx : 32` | 常见于 `TCONF`/不支持/跳过，也可能是 wrapper 状态 | 看 Summary 里 `skipped`、`broken`、`failed`。 |
| `all == 0` | judge 没抓到有效统计，或 case 没产生 Summary/ANSI 结果 | 归入 `no_stat_cases`，需要回看原始 case 输出。 |
| 全日志计分比单段低 | 后面同名 case 覆盖前面结果，或日志混入半截套件 | 必须先按 TEST GROUP 截段。 |
| `ltp-analyze.py` 分数比 judge 高很多 | 可能同时统计了逐行 TPASS 和 Summary，或合并了 musl/glibc 同名 case | 用它排障，不用它报最终分。 |
