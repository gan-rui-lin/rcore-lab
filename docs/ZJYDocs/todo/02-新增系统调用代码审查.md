# 新增系统调用代码审查报告

**日期**: 2026/06/04  
**审查范围**: epoll, eventfd, signalfd, POSIX timers, mremap, copy_file_range, rt_sigpending, rt_sigqueueinfo, user_mem

## 严重级别说明

- **P0** — 会导致内核 panic、死锁或数据损坏，需要立即修复
- **P1** — 功能行为错误，违反 Linux ABI 语义，用户态程序会收到错误结果
- **P2** — 次要问题，包括资源泄漏、缺失的边界检查、代码健壮性问题

## 1. copy_file_range: 从未写入目标文件 (P0)

**文件**: `os/src/syscall/fs.rs` 第 5916-5968 行

`sys_copy_file_range` 从源文件读取数据到内核 `buf` 中，但 **从未将数据写入目标文件 `dst_file`**。函数读完数据后直接返回 `bytes_read`，完全跳过了写入步骤。这意味着该系统调用声称成功复制了 N 字节，但实际上目标文件没有任何改变。

```rust
// 当前代码: 读取后直接返回，没有写入 dst_file
let bytes_read = if let Some(off) = src_offset {
    src_file.read_at_kernel(off, &mut buf)
} else {
    return errno(ENOSYS);
};
// BUG: 缺少 dst_file.write(...) 调用!
bytes_read as isize
```

此外，`off_out` 参数被标记为 `_off_out` 并被完全忽略，即使提供了目标偏移也不会使用。

**修复建议**: 读取数据后需要调用 `dst_file` 的写入方法（如 `write_at_kernel` 或类似接口），并正确处理 `off_out` 参数来更新目标文件偏移。

## 2. POSIX Timers: 全局表资源泄漏 (P1)

**文件**: `os/src/syscall/process.rs` 第 51-54 行, 第 5638-5656 行

### 2a. 进程退出不清理定时器

`POSIX_TIMERS` 是一个全局 `BTreeMap<(pid, timer_id), PosixTimer>`，但在进程退出时 (`exit_current_and_run_next`) 没有清理属于该进程的定时器条目。虽然 `cleanup_shm_for_process_exit` 在退出时被调用，但其中不包含 POSIX timer 的清理逻辑。

后果:
- 全局表不断增长，内存泄漏
- `posix_timers_check_expired` 在每次定时器中断中遍历所有条目，包括已死进程的定时器。已过期的僵尸定时器会持续产生 `(pid, signo)` 对，导致 `check_posix_timers` 在 `pid2process_snapshot()` 中找不到对应进程时白白遍历，虽然不会 crash，但浪费 CPU
- PID 复用后，旧定时器可能错误地向新进程发送信号

### 2b. POSIX_TIMER_NEXT_ID 全局递增，永不重置

`POSIX_TIMER_NEXT_ID` 是全局递增的，所有进程共享同一个 ID 空间。这不符合 Linux 语义，Linux 的 `timer_t` 是每进程独立的（通常从 0 开始）。虽然不会导致功能错误，但 LTP 测试用例 `timer_create04` 等可能会检查返回的 timer ID 值。

**修复建议**: 在进程退出路径中添加 POSIX timer 清理逻辑，移除所有 `(pid, *)` 键的条目。

## 3. EPOLL_REGISTRY: 资源泄漏且不清理 (P1)

**文件**: `os/src/syscall/fs.rs` 第 5859-5877 行

### 3a. 关闭 epoll fd 不会清理全局注册表

`epoll_unregister` 函数已经定义但标记为 `#[allow(dead_code)]`，在 `sys_close` 中从未被调用。当用户关闭 epoll fd 或进程退出时，`EPOLL_REGISTRY` 中的条目永远不会被移除。

后果:
- `Arc<EpollFile>` 永远无法释放，内存泄漏
- PID 复用 + fd 编号复用可能导致新进程的 epoll 操作意外命中旧条目

### 3b. dup2/fork 场景下 epoll fd 不一致

如果用户通过 `dup2` 将 epoll fd 复制到另一个编号，或者 `fork` 后子进程继承 epoll fd，全局注册表中的 `(pid, fd)` 键不会更新。子进程使用继承的 epoll fd 调用 `epoll_ctl` 时，会因为查找 `(child_pid, epfd)` 失败而返回 EBADF。

**修复建议**: 在 `sys_close` 中调用 `epoll_unregister(pid, fd)`，并在进程退出时批量清理。考虑使用进程内的 fd 表直接 downcast 来获取 `EpollFile`，而不是维护全局注册表。

## 4. POSIX Timers: 定时器中断路径竞态 (P1)

**文件**: `os/src/syscall/process.rs` 第 5638-5656 行, `os/src/timer.rs` 第 158-188 行

### 4a. posix_timers_check_expired 持锁时间过长

`posix_timers_check_expired` 在持有 `POSIX_TIMERS.exclusive_access()` 锁的情况下遍历整个定时器表。虽然 `UPIntrFreeCell` 会在持锁期间禁用中断，避免了嵌套死锁，但这意味着在定时器表很大时，整个检查期间中断被禁用，影响系统响应性。

### 4b. sigev_notify 被忽略

`sys_timer_create` 读取了 `sigev_signo` 但完全忽略了 `sigev_notify` 字段。按照 POSIX 规范:
- `SIGEV_NONE` (0): 定时器到期时不应发送信号
- `SIGEV_SIGNAL` (1): 发送 `sigev_signo` 指定的信号
- `SIGEV_THREAD` (2): 启动新线程执行回调

当前实现对所有定时器都发送信号，即使用户指定了 `SIGEV_NONE`。这会导致 LTP `timer_create` 系列测试失败。

**修复建议**: 读取并存储 `sigev_notify`，在 `posix_timers_check_expired` 中检查，`SIGEV_NONE` 时跳过信号投递。

## 5. eventfd: 字节序不一致 (P2)

**文件**: `os/src/fs/eventfd.rs` 第 91 行, 第 144 行

`read` 使用 `value.to_ne_bytes()`（native-endian），`write` 使用 `u64::from_ne_bytes()`（native-endian）。虽然 read/write 之间自洽（都是 native endian），但 Linux `eventfd` 的 ABI 规定使用 **host byte order**（也是 native endian），所以这在技术上是正确的。

但注释里写的是 "Write value as little-endian u64 to user buffer"，与实际的 `to_ne_bytes()` 行为不符（RISC-V 默认是 little-endian 所以实际等价，但注释具有误导性）。

**修复建议**: 修正注释，或统一使用 `to_le_bytes()` / `from_le_bytes()` 以匹配 RISC-V 硬件的 LE 特性并消除歧义。

## 6. signalfd4: 更新已有 fd 时不生效 (P1)

**文件**: `os/src/syscall/fs.rs` 第 5879-5897 行

当 `fd != -1` 时（更新已存在的 signalfd），函数直接返回 `fd as isize` 而不做任何操作。按照 Linux 语义，当 `fd >= 0` 时应该：

1. 验证 `fd` 指向一个有效的 signalfd
2. 更新该 signalfd 的信号掩码为新的 `mask`
3. 返回 `fd`

当前实现完全跳过了掩码更新。`SignalFdFile::update_mask` 方法已经实现但标记为 `#[allow(dead_code)]`，从未被调用。

```rust
// 当前代码: fd != -1 时什么都不做
} else {
    fd as isize  // BUG: 未调用 update_mask
}
```

**修复建议**: 在 `fd >= 0` 分支中，从进程 fd 表获取文件对象，downcast 为 `SignalFdFile`，调用 `update_mask(mask)`。

## 7. signalfd4: translated_ref 无安全检查 (P2)

**文件**: `os/src/syscall/fs.rs` 第 5884 行

```rust
let user_mask = *translated_ref(token, mask_ptr);
```

`translated_ref` 是 rCore 遗留的裸指针翻译函数，不会验证用户指针的有效性。如果 `mask_ptr` 是无效地址或 NULL，会直接解引用野指针，可能导致内核访问异常（在没有 guard page 的情况下可能不会 trap 而是读到垃圾数据）。

同样的问题存在于 `sys_copy_file_range` 第 5942 行:
```rust
Some(*translated_ref(token, off_in as *const i64) as usize)
```

**修复建议**: 使用 `read_from_user` 代替 `translated_ref`，它会正确检查用户指针有效性并返回 `Result`。

## 8. copy_file_range: translated_ref 读取 off_in 可能访问无效内存 (P1)

**文件**: `os/src/syscall/fs.rs` 第 5941-5942 行

除了上述第 7 点的安全问题外，`off_in` 是 `*mut i64` 类型（因为内核需要回写新偏移），但读取时强转为 `*const i64` 通过 `translated_ref` 读取。如果该指针跨页边界或指向只读页面，`translated_ref` 可能返回错误的物理地址。

## 9. TimerCondVar::partial_cmp 整数溢出 (P2)

**文件**: `os/src/timer.rs` 第 32-37 行

```rust
fn partial_cmp(&self, other: &Self) -> Option<Ordering> {
    let a = -(self.expire_ms as isize);
    let b = -(other.expire_ms as isize);
    Some(a.cmp(&b))
}
```

`expire_ms` 是 `usize`。在 RV64 上，如果 `expire_ms > isize::MAX`（约 9.2e18），`as isize` 转换会产生负值，然后取反后变为正值。虽然在实际运行中 `expire_ms` 不太可能超过 `isize::MAX`（对应约 292 亿年），但这是一个不健壮的写法。

更好的实现:
```rust
Some(other.expire_ms.cmp(&self.expire_ms))  // 反转比较实现最小堆
```

## 10. mremap: 页面复制不处理未映射页 (P1)

**文件**: `os/src/syscall/process.rs` 第 5706-5725 行

在 `MREMAP_MAYMOVE` 路径中，页面复制循环使用 `translate_va` 来获取源和目标物理地址:

```rust
if let Some(src_pa) = page_table.translate_va(VirtAddr::from(src_va)) {
    if let Some(dst_pa) = page_table.translate_va(VirtAddr::from(dst_va)) {
        unsafe { core::ptr::copy_nonoverlapping(src_ptr, dst_ptr, chunk); }
    }
}
```

如果源页面未映射（demand-paged 或 lazy alloc），`translate_va` 返回 `None`，该页面的数据会被静默跳过。这意味着 mremap 后新区域中某些页面可能包含 mmap 初始化的零值而非原始数据。

此外，新映射通过 `sys_mmap` 使用 `MAP_PRIVATE|MAP_ANONYMOUS` 创建，权限硬编码为 `PROT_READ|PROT_WRITE`，忽略了原始映射可能具有的 `PROT_EXEC` 权限，这对于代码段的 mremap 会导致执行权限丢失。

## 11. mremap: 缩小映射时不释放多余页面 (P2)

**文件**: `os/src/syscall/process.rs` 第 5692 行

```rust
if new_size_aligned <= old_size_aligned {
    return old_addr as isize;
}
```

缩小映射时直接返回旧地址，不会 unmap 多余的页面。Linux 在缩小时会释放 `[old_addr + new_size, old_addr + old_size)` 范围的页面。

## 12. signalfd: 不检查 EINTR (P2)

**文件**: `os/src/fs/signalfd.rs` 第 69-129 行

`SignalFdFile::read` 在阻塞等待信号时，调用 `suspend_current_and_run_next()` 但之后不检查是否有待处理的未屏蔽信号（即不处理 EINTR 语义）。如果进程收到一个不在 signalfd 掩码中的信号，read 应该返回 EINTR，但当前实现会继续循环等待。

对比 `eventfd` 的实现正确地检查了 `has_pending_unmasked_signal(true)`。

## 13. eventfd: EAGAIN/EINTR/EINVAL 共用错误标志 (P2)

**文件**: `os/src/fs/eventfd.rs` 第 75-76 行, 第 119 行

```rust
pub const EVENTFD_EAGAIN: usize = usize::MAX - 1;
// ...
if buf.len() < 8 {
    return usize::MAX; // EINVAL sentinel
}
// ...
return usize::MAX; // EINTR
```

`read` 和 `write` 使用 `usize::MAX` 同时表示 EINVAL 和 EINTR 两种不同的错误，调用方无法区分。`EVENTFD_EAGAIN` 使用 `usize::MAX - 1`，但其他错误都是 `usize::MAX`。应该为每种错误定义独立的 sentinel 值，或者改用 `Result` 类型。

## 14. epoll_pwait: 不处理 sigmask 参数 (P2)

**文件**: `os/src/syscall/fs.rs` 第 5746 行

函数签名只有 `(epfd, events, maxevents, timeout)` 四个参数，缺少 Linux `epoll_pwait` 的第五个参数 `sigmask` 和第六个参数 `sigsetsize`。`epoll_pwait` 与 `epoll_wait` 的关键区别就是可以原子地设置信号掩码，省略此参数会导致信号相关的竞态条件。

## 15. sys_rt_sigpending: 仅返回线程级 pending 信号 (P2)

**文件**: `os/src/syscall/process.rs` 第 3795-3813 行

```rust
let pending = task.with_signals(|signals| flags_to_user_mask(signals.signal_pending));
```

该实现仅返回当前线程的 pending 信号，但 Linux 的 `rt_sigpending` 应该返回 **线程 pending 和进程 pending 的并集**。进程级别的 pending 信号（如通过 `kill` 发送给进程的信号）可能存储在不同的位置。

## 16. sys_rt_sigqueueinfo: 丢弃 siginfo (P2)

**文件**: `os/src/syscall/process.rs` 第 3815-3818 行

```rust
pub fn sys_rt_sigqueueinfo(pid: isize, sig: i32, _info: *const u8) -> isize {
    sys_kill(pid, sig)
}
```

`_info` 参数（`siginfo_t` 结构体指针）被完全忽略。`rt_sigqueueinfo` 的核心价值是携带 `siginfo_t` 数据（包括 `si_value`, `si_pid`, `si_uid` 等），这些信息应该在信号投递时传递给处理函数。当前实现退化为 `kill`，LTP 的 `sigqueue01` 等测试会失败。

## 17. timer_create: timer_t 类型大小不匹配 (P1)

**文件**: `os/src/syscall/process.rs` 第 5479-5482 行

```rust
let id_bytes = timer_id.to_ne_bytes();  // usize = 8 bytes on rv64
if let Err(err) = copy_to_user(token, timerid as *mut u8, &id_bytes) {
```

`timer_t` 在 Linux 上被定义为 `int`（4 字节），但这里写入了 `usize`（8 字节）。这会覆盖用户栈上紧邻 `timerid` 后面的 4 字节数据，可能导致栈数据损坏。

函数签名中 `timerid: *mut usize` 也应该改为 `timerid: *mut i32`。

**修复建议**: 使用 `(timer_id as i32).to_ne_bytes()` 写入 4 字节。

## 18. legacy_fork_write_fallback: 绕过写权限检查 (P2)

**文件**: `os/src/syscall/user_mem.rs` 第 501-513 行

```rust
fn legacy_fork_write_fallback(
    token: usize, ptr: *const u8, len: usize,
) -> Option<Vec<&'static mut [u8]>> {
    if !is_user_read_mapped(token, ptr, len) {
        return None;
    }
    if translated_byte_buffer_checked(token, ptr, len, false).is_none() {
        return None;
    }
    Some(translated_byte_buffer(token, ptr, len))
}
```

该函数只检查了页面是否可读 (`is_user_read_mapped` + `translated_byte_buffer_checked(..., false)`)，然后通过 `translated_byte_buffer` 返回可变引用。这意味着即使页面是只读映射的（例如 `.rodata` 段），调用者也能获得可写的 `&mut [u8]` 切片并写入数据。

这是一个有意的 fallback 设计（用于 fork 后的 COW 页面尚未被 demand-fault 处理的场景），但其名称和注释应该更清楚地说明其安全性假设和适用范围。在非 fork 场景下如果被误用可能导致写入只读内存。

## 19. EpollFile: cloexec 是不可变的 (P2)

**文件**: `os/src/fs/epoll.rs` 第 26 行

```rust
pub struct EpollFile {
    inner: UPIntrFreeCell<EpollInner>,
    cloexec: bool,
}
```

`cloexec` 字段不在 `UPIntrFreeCell` 内部，这意味着它在创建后不可修改。Linux 允许通过 `fcntl(F_SETFD, FD_CLOEXEC)` 动态修改 close-on-exec 标志。类似问题也存在于 `EventFdFile::flags` 和 `SignalFdFile::nonblock`。

## 20. check_posix_timers: 时间单位转换精度损失 (P2)

**文件**: `os/src/timer.rs` 第 163 行

```rust
let current_us = current_ms as u64 * 1000;
```

将毫秒转换为微秒时乘以 1000，但 POSIX timer 的 `value_us` 是通过 `get_time_us()` 设置的（真正的微秒精度）。这种从毫秒乘回微秒的转换最多会有 999 微秒的误差，可能导致定时器在预期时间前最多 1 毫秒触发。

**修复建议**: 在 `check_posix_timers` 中直接使用 `get_time_us()` 而不是从 `current_ms` 转换。

1. **P0-1**: `copy_file_range` 不写目标文件 -- 这是完全无效的系统调用
2. **P1-17**: `timer_create` 写入 8 字节到 4 字节的 `timer_t`，可能破坏用户栈

4. **P1-4**: `sigev_notify` 处理 -- 影响 LTP timer 系列测试
5. **P1-6**: signalfd4 掩码更新 -- 影响 signalfd 功能正确性
6. **P1-10**: mremap 数据丢失 -- 影响使用 mremap 的程序（如 realloc 某些实现）
