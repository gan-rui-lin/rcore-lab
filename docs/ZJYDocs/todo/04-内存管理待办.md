# 内存管理待办事项

**日期**: 2026/06/04

---

## 1. COW fork 写回退安全性审查

**现状**: `user_mem.rs:legacy_fork_write_fallback` 已移除进程名限制，使所有 forked 子进程都能通过读映射回退写入。

**风险**: 该回退绕过了写权限检查（`translated_byte_buffer_checked(token, ptr, len, false)` 使用 `require_writable=false`），这意味着即使页面没有写权限，内核也能写入用户空间。

**待办**:
- [ ] 评估是否存在安全风险：恶意程序可能利用此回退写入只读映射
- [ ] 考虑更精确的方案：只在 `handle_cow_fault` 返回 false 且页面确实是 COW 映射时才回退
- [ ] 添加日志记录回退触发的频率和场景

---

## 2. mremap 实现不完整

**现状**: `sys_mremap` 只有最基本实现：
- 缩小/相同大小 → 直接返回原地址
- 扩大 + MREMAP_MAYMOVE → mmap 新区域 + 逐页拷贝 + munmap 旧区域
- 扩大无 MREMAP_MAYMOVE → 返回 ENOMEM

**缺失**:
- [ ] 原地扩展（检查后续虚拟地址是否空闲，如果空闲则直接扩展 VMA）
- [ ] MREMAP_FIXED 支持（指定新地址）
- [ ] 缩小时应该 munmap 多余部分，而不是什么都不做
- [ ] 文件映射的 mremap（需要更新 file_back 信息）
- [ ] 共享映射的 mremap（涉及 shared_frames 标记）

**影响**: glibc malloc 在堆扩展时使用 mremap，当前简化实现可能导致内存浪费。

## 3. mlock/mlockall 实现

**现状**: `sys_mlock` 存在但返回 ENOSYS，`sys_mlockall` 也是。

**LTP 影响**: mlock01, mlock02, mlock03, mlockall01 等多个测试 TBROK。

**待办**:
- [ ] mlock/munlock：标记页面为不可换出（在 rCore 中没有换页，可以直接返回 0）
- [ ] mlockall/munlockall：同上
- [ ] mlock2：支持 MLOCK_ONFAULT 标志
