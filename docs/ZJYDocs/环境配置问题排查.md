## 网络问题

### 问题 1: DNS 解析失败

**症状**:
```
curl: (6) Could not resolve host: static.rust-lang.org
```

**诊断**:
```bash
# 测试 DNS 解析
ping -c 3 static.rust-lang.org

# 检查 DNS 配置
scutil --dns | head -20
```

**解决方案**:
1. **使用 Homebrew 替代方案**（推荐）:
   ```bash
   brew install rust
   brew install rustup
   ```

2. **配置代理**（如果有代理服务器）:
   ```bash
   export http_proxy=http://proxy:port
   export https_proxy=http://proxy:port
   curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
   ```

3. **使用国内镜像**:
   ```bash
   # 配置 rustup 镜像
   export RUSTUP_DIST_SERVER=https://mirrors.ustc.edu.cn/rust-static
   export RUSTUP_UPDATE_ROOT=https://mirrors.ustc.edu.cn/rust-static/rustup

   # 配置 cargo 镜像（~/.cargo/config.toml）
   [source.crates-io]
   replace-with = 'ustc'

   [source.ustc]
   registry = "https://mirrors.ustc.edu.cn/crates.io-index"
   ```

### 问题 2: 网络超时

**症状**:
```
timeout waiting for server response
```

**解决方案**:
```bash
# 增加超时时间
export CARGO_NET_GIT_FETCH_WITH_CLI=true
export CARGO_HTTP_TIMEOUT=300

# 或在 Cargo.toml 同级目录创建 .cargo/config.toml
[http]
timeout = 300
```

## 编译错误

### 错误 1: sed 正则表达式错误

**症状**:
```
sed: 1: "s/^ch([0-9]+).*\1/p": unterminated substitute in regular expression
```

**原因**: macOS BSD sed 与 GNU sed 语法差异

**解决方案**: 修改 `os/Makefile` 第 34 行:
```makefile
# 修改前
CHAPTER ?= $(shell git rev-parse --abbrev-ref HEAD | sed -nE 's/^ch([0-9]+).*$/\1/p')

# 修改后（注意 $$ 双重转义）
CHAPTER ?= $(shell git rev-parse --abbrev-ref HEAD | sed -nE 's/^ch([0-9]+).*$$/\1/p')
```

### 错误 2: rustup: command not found

**症状**:
```
/bin/sh: rustup: command not found
make: *** [env] Error 127
```

**诊断**:
```bash
which rustup
echo $PATH
```

**解决方案**:
1. 安装 rustup:
   ```bash
   brew install rustup
   ```

2. 配置 PATH（添加到 `~/.zshrc`）:
   ```bash
   export PATH="/opt/homebrew/opt/rustup/bin:$PATH"
   source ~/.zshrc
   ```

3. 验证:
   ```bash
   rustup --version
   ```

### 错误 3: rust-objcopy: command not found

**症状**:
```
/bin/sh: rust-objcopy: command not found
cp: target/riscv64gc-unknown-none-elf/release/initcode.bin: No such file or directory
```

**原因**: cargo-binutils 未安装或不在 PATH 中

**解决方案**:
1. 安装 cargo-binutils:
   ```bash
   cargo +stable install cargo-binutils
   ```

2. 添加到 PATH（`~/.zshrc`）:
   ```bash
   export PATH="$HOME/.cargo/bin:$PATH"
   source ~/.zshrc
   ```

3. 验证:
   ```bash
   which rust-objcopy
   which rust-objdump
   ```

### 错误 4: 版本不兼容

**症状**:
```
rustc 1.80.0-nightly is not supported by the following package:
  indexmap@2.13.0 requires rustc 1.82
```

**解决方案**: 使用 stable 工具链安装:
```bash
cargo +stable install <package-name>
```

## 工具链问题

### 问题 1: RISC-V 目标未安装

**症状**:
```
error[E0463]: can't find crate for `core`
  = note: the `riscv64gc-unknown-none-elf` target may not be installed
```

**解决方案**:
```bash
# 检查已安装目标
rustup target list | grep riscv

# 安装 RISC-V 目标
rustup target add riscv64gc-unknown-none-elf --toolchain nightly-2024-05-02

# 验证
rustup target list | grep "riscv64gc-unknown-none-elf (installed)"
```

### 问题 2: rust-src 组件缺失

**症状**:
```
error: the `rust-src` component is required
```

**解决方案**:
```bash
rustup component add rust-src --toolchain nightly-2024-05-02
```

### 问题 3: llvm-tools 缺失

**症状**:
```
error: failed to run custom build command for `os v0.1.0`
  Could not find llvm-tools
```

**解决方案**:
```bash
rustup component add llvm-tools-preview --toolchain nightly-2024-05-02
```

### 问题 4: 工具链版本冲突

**检查当前工具链**:
```bash
rustup show
```

**预期输出**:
```
active toolchain
----------------
nightly-2024-05-02-aarch64-apple-darwin
active because: overridden by '/Users/mac/Desktop/project/rcore-lab/rust-toolchain.toml'
installed targets:
  aarch64-apple-darwin
  riscv64gc-unknown-none-elf
```

## QEMU 运行问题

### 问题 1: QEMU 未安装

**症状**:
```
qemu-system-riscv64: command not found
```

**解决方案**:
```bash
brew install qemu
qemu-system-riscv64 --version
```

### 问题 2: QEMU 无法启动

**诊断**:
```bash
# 检查是否有其他 QEMU 实例
ps aux | grep qemu

# 检查端口占用（如果使用网络）
lsof -i :1234
```

**解决方案**:
```bash
# 结束所有 QEMU 进程
pkill -f qemu-system-riscv64

# 重新运行
make run
```

### 问题 3: 找不到启动文件

**症状**:
```
qemu-system-riscv64: could not load kernel 'target/riscv64gc-unknown-none-elf/release/os.bin': No such file or directory
```

**诊断**:
```bash
# 检查构建输出
ls -la target/riscv64gc-unknown-none-elf/release/os*

# 检查 bootloader
ls -la ../bootloader/
```

**解决方案**:
1. 重新构建:
   ```bash
   make clean
   make build
   ```

2. 检查 Makefile 路径配置

## macOS 特定问题

### 问题 1: Homebrew 路径问题

**Apple Silicon (ARM64) Mac**:
- Homebrew 位置: `/opt/homebrew/`
- PATH 设置: `/opt/homebrew/bin:/opt/homebrew/opt/rustup/bin`

**Intel Mac**:
- Homebrew 位置: `/usr/local/`
- PATH 设置: `/usr/local/bin:/usr/local/opt/rustup/bin`

**验证 Homebrew**:
```bash
which brew
brew --prefix
```

### 问题 2: zsh vs bash

**检查当前 shell**:
```bash
echo $SHELL
```

**配置文件**:
- zsh: `~/.zshrc`
- bash: `~/.bash_profile` 或 `~/.bashrc`

**正确配置示例** (`~/.zshrc`):
```bash
# Homebrew
eval "$(/opt/homebrew/bin/brew shellenv)"

# rustup
export PATH="/opt/homebrew/opt/rustup/bin:$PATH"

# cargo binaries
export PATH="$HOME/.cargo/bin:$PATH"
```

### 问题 3: 权限问题

**症状**:
```
Permission denied
```

**解决方案**:
```bash
# 修复 cargo 目录权限
chmod -R u+w ~/.cargo

# 修复 rustup 目录权限
chmod -R u+w ~/.rustup

# 如果是 Homebrew
sudo chown -R $(whoami) $(brew --prefix)/*
```

### 问题 4: Xcode Command Line Tools

某些编译工具需要 Xcode Command Line Tools:

```bash
# 安装
xcode-select --install

# 验证
xcode-select -p
```

## 完整环境检查清单

使用以下脚本检查环境完整性:

```bash
#!/bin/bash

echo "=== rCore-Lab 环境检查 ==="
echo

echo "1. 检查 Rust 工具链..."
command -v rustup >/dev/null 2>&1 && echo "✅ rustup 已安装" || echo "❌ rustup 未安装"
command -v cargo >/dev/null 2>&1 && echo "✅ cargo 已安装" || echo "❌ cargo 未安装"
command -v rustc >/dev/null 2>&1 && echo "✅ rustc 已安装" || echo "❌ rustc 未安装"

echo
echo "2. 检查 RISC-V 目标..."
rustup target list | grep -q "riscv64gc-unknown-none-elf (installed)" && \
  echo "✅ RISC-V 目标已安装" || echo "❌ RISC-V 目标未安装"

echo
echo "3. 检查必需组件..."
rustup component list | grep -q "rust-src (installed)" && \
  echo "✅ rust-src 已安装" || echo "❌ rust-src 未安装"
rustup component list | grep -q "llvm-tools" && \
  echo "✅ llvm-tools 已安装" || echo "❌ llvm-tools 未安装"

echo
echo "4. 检查二进制工具..."
command -v rust-objcopy >/dev/null 2>&1 && echo "✅ rust-objcopy 已安装" || echo "❌ rust-objcopy 未安装"
command -v rust-objdump >/dev/null 2>&1 && echo "✅ rust-objdump 已安装" || echo "❌ rust-objdump 未安装"

echo
echo "5. 检查 QEMU..."
command -v qemu-system-riscv64 >/dev/null 2>&1 && echo "✅ QEMU 已安装" || echo "❌ QEMU 未安装"

echo
echo "6. 检查工具链版本..."
rustup show | grep -A 1 "active toolchain"

echo
echo "=== 检查完成 ==="
```

保存为 `check_env.sh`，然后运行:
```bash
chmod +x check_env.sh
./check_env.sh
```

## 快速修复脚本

如果环境出现问题，可以运行此脚本重新配置:

```bash
#!/bin/bash

set -e

echo "开始修复 rCore-Lab 环境..."

# 1. 确保 Homebrew 可用
if ! command -v brew &> /dev/null; then
    echo "❌ Homebrew 未安装，请先安装 Homebrew"
    exit 1
fi

# 2. 安装/更新 rustup
echo "安装 rustup..."
brew install rustup 2>/dev/null || brew upgrade rustup 2>/dev/null || true

# 3. 配置 PATH
export PATH="/opt/homebrew/opt/rustup/bin:$PATH"
export PATH="$HOME/.cargo/bin:$PATH"

# 4. 初始化工具链
echo "初始化工具链..."
rustup default stable

# 5. 安装 nightly 工具链
echo "安装 nightly-2024-05-02..."
rustup toolchain install nightly-2024-05-02

# 6. 安装组件
echo "安装必需组件..."
rustup component add rust-src llvm-tools-preview --toolchain nightly-2024-05-02

# 7. 安装 RISC-V 目标
echo "安装 RISC-V 目标..."
rustup target add riscv64gc-unknown-none-elf --toolchain nightly-2024-05-02

# 8. 安装 cargo-binutils
echo "安装 cargo-binutils..."
cargo +stable install cargo-binutils --force

# 9. 确保 QEMU 已安装
echo "检查 QEMU..."
brew list qemu &>/dev/null || brew install qemu

# 10. 更新 shell 配置
echo "更新 shell 配置..."
grep -q "/opt/homebrew/opt/rustup/bin" ~/.zshrc || \
  echo 'export PATH="/opt/homebrew/opt/rustup/bin:$PATH"' >> ~/.zshrc
grep -q ".cargo/bin" ~/.zshrc || \
  echo 'export PATH="$HOME/.cargo/bin:$PATH"' >> ~/.zshrc

echo "✅ 环境修复完成！"
echo "请运行: source ~/.zshrc"
echo "然后测试: cd os && make run"
```

保存为 `fix_env.sh`，然后运行:
```bash
chmod +x fix_env.sh
./fix_env.sh
source ~/.zshrc
```
