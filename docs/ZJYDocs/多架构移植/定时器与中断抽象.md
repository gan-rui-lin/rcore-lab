## 一、问题域：定时器和中断控制器的架构差异

定时器和中断控制器是操作系统调度和设备管理的基础。各架构差异极大：

| 功能 | RISC-V | x86-64 | AArch64 | LoongArch |
|------|--------|--------|---------|-----------|
| 定时器类型 | SBI 回调式 | LAPIC 周期式 | Generic Timer | 内置周期式 |
| 时间源 | rdtime CSR | RDTSC 指令 | CNTPCT_EL0 | 专用 CSR |
| 中断控制器 | PLIC | APIC | GIC | 内置控制器 |
| 中断使能 | sie CSR | LAPIC 寄存器 | GIC 寄存器 | ecfg CSR |

## 二、定时器抽象

### 2.1 通用 Time 结构体

```rust
// arch/src/time.rs
pub struct Time(usize);  // 包装原始计数值

impl Time {
    pub fn get_freq() -> usize;    // 各架构不同频率
    pub fn now() -> Self;          // 读取当前时间
    pub fn to_usec(&self) -> usize {
        self.0 * 1_000_000 / Self::get_freq()
    }
    pub fn to_msec(&self) -> usize {
        self.0 * 1_000 / Self::get_freq()
    }
}
```

内核代码只使用 `Time::now()` 和 `time.to_usec()` 等方法，无需知道底层计时机制。

### 2.2 各架构定时器实现对比

#### RISC-V：SBI 回调式

```rust
// arch/src/riscv64/timer.rs
const TICKS_PER_SEC: usize = CLOCK_FREQ / 100;  // 10ms 一次

impl Time {
    pub fn get_freq() -> usize { CLOCK_FREQ }          // 板级常量
    pub fn now() -> Self { Self(riscv::time::read()) }  // rdtime CSR
}

pub fn set_next_timeout() {
    sbi_rt::set_timer((riscv::time::read() + TICKS_PER_SEC) as u64);
}

pub fn init() {
    unsafe { sie::set_stimer(); }  // 使能 S 级时钟中断
    set_next_timeout();
}
```

RISC-V 的定时器是**单次触发**的——每次中断后必须重新设置下次触发时间，通过 SBI 调用实现。

#### x86-64：LAPIC 周期式

```rust
// arch/src/x86_64/time.rs
static mut CPU_FREQ_MHZ: usize = 4000;  // 默认 4GHz

impl Time {
    pub fn get_freq() -> usize { unsafe { CPU_FREQ_MHZ * 1_000_000 } }
    pub fn now() -> Self { Self(unsafe { _rdtsc() as usize }) }  // RDTSC 指令
}

pub fn init_early() {
    // 从 CPUID 获取 TSC 频率
    let cpuid = raw_cpuid::CpuId::new();
    if let Some(freq) = cpuid.get_processor_frequency_info() {
        CPU_FREQ_MHZ = freq.processor_max_frequency() as usize;
    }

    // 配置 LAPIC 定时器为周期模式
    let lapic = local_apic();
    lapic.set_timer_mode(TimerMode::Periodic);
    lapic.set_timer_divide(TimerDivide::Div256);
    lapic.set_timer_initial(0x200000);  // 初始计数值
    lapic.enable_timer();
}
```

x86-64 使用两套独立机制：**RDTSC 读取时间**（高精度但只读），**LAPIC 定时器产生中断**（周期式自动触发）。

#### AArch64：Generic Timer

```rust
// arch/src/aarch64/timer.rs
impl Time {
    pub fn get_freq() -> usize {
        CNTFRQ_EL0.get() as usize   // 从硬件寄存器读取频率
    }
    pub fn now() -> Self {
        Self(CNTPCT_EL0.get() as usize)  // 物理计数器
    }
}

pub fn set_next_timer() {
    CNTP_TVAL_EL0.set((Time::get_freq() / 1000) as u64);  // 1ms 后触发
}

pub fn init() {
    CNTP_CTL_EL0.set(1);           // 使能物理定时器
    gic::set_enable(TIMER_IRQ_NUM, true);  // 在 GIC 中使能定时器中断
    CNTP_TVAL_EL0.set(0);          // 立即触发首次中断
}
```

ARM 的 Generic Timer 同时提供**计数器**（CNTPCT）和**比较器**（TVAL/CVAL），计数器用于读时间，比较器用于设置中断。

#### LoongArch64：内置定时器

```rust
// arch/src/loongarch64/timer.rs
static FREQ: Lazy<usize> = Lazy::new(|| get_timer_freq());

impl Time {
    pub fn get_freq() -> usize { *FREQ }
    pub fn now() -> Self { Self(LoongArchTime::read()) }
}

pub fn init_timer() {
    let ticks = (Time::get_freq() / 1000 + 3) & !3;  // 1ms，4 对齐
    set_timer(true, ticks, true);  // periodic=true, enable=true
    // 使能定时器中断 + 软中断 + 硬中断
    ecfg::set_lie_with_index(11, true);  // Timer
    ecfg::set_lie_with_index(0, true);   // SWI0
    ecfg::set_lie_with_index(1, true);   // SWI1
    ecfg::set_lie_with_index(2, true);   // HWI0
}
```

LoongArch 的定时器配置通过 TCFG CSR 完成，支持周期模式。

### 2.3 定时器触发模式对比

| 架构 | 触发模式 | 重设方式 | 时钟精度 |
|------|---------|---------|---------|
| RISC-V | 单次触发 | 中断后调用 SBI set_timer | 由板级决定（如 12.5MHz） |
| x86-64 | 周期触发 | LAPIC 自动重装 | TSC 频率（GHz 级） |
| AArch64 | 单次触发 | 中断后设置 TVAL | 由硬件频率决定 |
| LoongArch | 周期触发 | 硬件自动重装 | 由固件提供频率 |

## 三、中断控制器抽象

### 3.1 中断使能/禁用

各架构提供相同签名的函数：

```rust
pub fn enable_irq();           // 使能外部中断
pub fn disable_irq();          // 禁用外部中断
pub fn enable_external_irq();  // 仅使能外部设备中断
```

#### RISC-V
```rust
pub fn enable_irq() {
    unsafe { sie::set_sext(); sie::set_ssoft(); }
}
pub fn disable_irq() {
    unsafe { sie::clear_sext(); sie::clear_ssoft(); }
}
```

#### x86-64
通过 LAPIC 和 IDT 管理中断向量。

#### AArch64
通过 GIC（Generic Interrupt Controller）管理：
```rust
pub fn set_enable(irq_num: usize, enabled: bool) {
    GIC.lock().set_enable(irq_num, enabled);
}
pub fn handle_irq<F>(f: F) where F: FnOnce(u32) {
    let irq = GIC.lock().get_and_acknowledge_interrupt();
    f(irq);
    GIC.lock().end_interrupt(irq);
}
```

### 3.2 外部中断处理流程

所有架构的外部中断最终都回到 `TrapType::SupervisorExternal`，由内核统一处理设备中断：

```rust
// os/src/main.rs（架构无关）
TrapType::SupervisorExternal => {
    // 处理外部设备中断（网卡、磁盘等）
    handle_external_interrupt();
}
```

## 四、中断控制器差异

| 特性 | PLIC (RISC-V) | APIC (x86) | GIC (ARM) | LoongArch 内置 |
|------|---------------|------------|-----------|-------------|
| 最大中断数 | 1024 | 256 | 1024 | 依平台 |
| 中断优先级 | 支持 | 支持 | 支持 | 支持 |
| 中断分发 | 按 hart | 按 CPU (IPI) | 按 CPU (SGI/PPI/SPI) | 按核心 |
| EOI 机制 | claim/complete | APIC EOI 寄存器 | IAR/EOIR | 硬件自动 |
| 核间中断 | SBI send_ipi | APIC IPI | GIC SGI | 专用 CSR |

## 五、与 rcore-lab 的对比

rcore-lab 当前的定时器（`os/src/timer.rs`）：

```rust
// 直接使用 RISC-V SBI
use crate::sbi::set_timer;
use riscv::register::time;

pub fn set_next_trigger() {
    set_timer(get_time() + CLOCK_FREQ / TICKS_PER_SEC);
}
```

**改造要点**：
1. 将 `Time` 结构体移到 `arch/` 中，各架构实现 `now()` 和 `get_freq()`
2. 将 `set_next_trigger()` 移到 `arch/` 中（各架构触发机制不同）
3. 内核只调用 `Time::now()` 和 `time.to_usec()` 等通用方法
4. 中断使能/禁用通过 `enable_irq()` / `disable_irq()` 统一接口
