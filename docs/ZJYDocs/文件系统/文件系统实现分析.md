## 概述

### 整体架构

rCore-lab 实现了一个**分层文件系统架构**：

```
┌─────────────────────────────────────────┐
│     系统调用层 (os/src/syscall/fs.rs)   │
├─────────────────────────────────────────┤
│     VFS 抽象层 (os/src/fs/vfs/)         │
│     - 统一的 VfsInode trait             │
│     - 路径解析与挂载管理                │
├─────────────────────────────────────────┤
│          具体文件系统实现                │
│  ┌─────────┬──────────┬──────────┐     │
│  │ EasyFS  │  FAT32   │  EXT4    │     │
│  └─────────┴──────────┴──────────┘     │
├─────────────────────────────────────────┤
│    块设备层 (BlockDevice trait)         │
│    - VirtIO Block Device                │
└─────────────────────────────────────────┘
```

### 已实现的文件系统

| 文件系统 | 状态 | 实现方式 | Feature Flag |
|---------|------|---------|--------------|

| **EXT4** | ✅ 完整 | lwext4_rust 库 | `ext4` (默认启用) |

## VFS 虚拟文件系统

### VFS 核心结构

#### 1. VfsInode Trait

定义了统一的文件/目录操作接口：

```rust
pub trait VfsInode: Send + Sync {
    // 基本属性
    fn kind(&self) -> VfsNodeKind;           // File 或 Dir
    fn size(&self) -> usize;                  // 文件大小
    fn is_dir(&self) -> bool;                // 是否为目录

    // 文件操作
    fn read_at(&self, offset: usize, buf: &mut [u8]) -> usize;
    fn write_at(&self, offset: usize, buf: &[u8]) -> usize;
    fn truncate(&self);                       // 清空文件

    // 目录操作
    fn lookup(&self, name: &str) -> Option<Arc<dyn VfsInode>>;
    fn create(&self, name: &str) -> Option<Arc<dyn VfsInode>>;
    fn create_dir(&self, name: &str) -> Option<Arc<dyn VfsInode>>;
    fn remove(&self, name: &str, is_dir: bool) -> bool;
    fn list(&self) -> Vec<String>;            // 列出目录内容
}
```

**设计特点**：
- 使用 trait object (`Arc<dyn VfsInode>`) 实现多态
- 所有文件系统都必须实现这个 trait
- 提供了文件和目录的统一抽象

#### 2. Vfs 管理器

负责挂载点管理和路径解析：

```rust
pub(crate) struct Vfs {
    mounts: Vec<MountPoint>,  // 挂载点列表
}

struct MountPoint {
    path: String,                    // 挂载路径，如 "/"
    root: Arc<dyn VfsInode>,         // 根 inode
    #[cfg(feature = "ext4")]
    _ext4_guard: Option<Arc<Ext4Fs>>, // ext4 生命周期管理
}
```

**核心功能**：

1. **路径解析** (`resolve`):
   ```rust
   pub(crate) fn resolve(&self, path: &str) -> Option<Arc<dyn VfsInode>>
   ```
   - 规范化路径（处理 `.` 和 `..`）
   - 找到最佳匹配的挂载点
   - 逐级 lookup 直到找到目标文件

2. **挂载管理**:
   ```rust
   pub(crate) fn mount_root(&mut self, root: Arc<dyn VfsInode>)
   pub(crate) fn mount_root_ext4(&mut self, root: Arc<dyn VfsInode>, guard: Arc<Ext4Fs>)
   ```

3. **路径规范化** (`normalize_path`):
   ```rust
   "/a/b/../c" -> "/a/c"
   "/a/./b"    -> "/a/b"
   ```

#### 3. Dentry (目录项缓存)

```rust
pub struct Dentry {
    name: String,
    parent: Option<Weak<Dentry>>,
    inode: Arc<dyn VfsInode>,
}
```

**用途**：
- 提供路径到 inode 的缓存
- 支持从子节点向上追溯到根
- 目前标记为 `#[allow(dead_code)]`（未完全启用）

### 挂载接口

```rust
// os/src/fs/vfs/mount.rs

pub fn mount_easyfs() -> Result<(), i32>    // 挂载 EasyFS 为根
pub fn mount_fat32() -> Result<(), i32>      // 挂载 FAT32 为根
pub fn mount_fat32_auto() -> bool            // 自动检测并挂载 FAT32

#[cfg(feature = "ext4")]
pub fn mount_ext4(total_bytes: i64) -> Result<(), i32>  // 挂载 EXT4
pub fn mount_ext4_auto() -> bool              // 自动检测并挂载 EXT4
```

**自动检测机制**：
- `mount_ext4_auto()`: 读取超级块魔数 `0xEF53`
- `mount_fat32_auto()`: 尝试挂载，失败返回 false

## FAT32 实现

### 概述

使用 **rust-fatfs** 库（`vendor/rust-fatfs`）实现。

**特点**：
- ✅ 成熟的 FAT32 实现
- ✅ 支持长文件名 (LFN)
- ✅ Unicode 支持
- ✅ 兼容性好（可与 Windows/Linux 互操作）

### 依赖配置

```toml
# os/Cargo.toml
fatfs = {
    path = "../vendor/rust-fatfs",
    default-features = false,
    features = ["alloc", "lfn", "unicode"]
}
```

**Features 说明**：
- `alloc`: 使用 alloc 而非 std
- `lfn`: 长文件名支持
- `unicode`: Unicode 文件名

### 目录结构

```
os/src/fs/vfs/fat32/
├── disk.rs       # Fat32Disk: BlockDevice -> fatfs 块设备适配
├── fs.rs         # Fat32Fs: 文件系统实例管理
├── inode.rs      # Fat32Inode -> VfsInode 适配
└── mod.rs
```

### 块设备适配

```rust
// os/src/fs/vfs/fat32/disk.rs

pub struct Fat32Disk {
    device: Arc<dyn BlockDevice>,
}

// 实现 fatfs 库要求的 Read + Write + Seek trait
impl fatfs::Read for Fat32Disk { ... }
impl fatfs::Write for Fat32Disk { ... }
impl fatfs::Seek for Fat32Disk { ... }
```

**关键点**：
- fatfs 库需要 Read/Write/Seek 语义
- 底层是块设备（512 字节块）
- 需要处理跨块读写

### VFS 适配

```rust
// os/src/fs/vfs/fat32/inode.rs

pub struct Fat32Inode {
    path: String,              // 文件路径
    kind: VfsNodeKind,         // File 或 Dir
    fs: Arc<UPSafeCell<Fat32Fs>>,  // 文件系统引用
}

impl VfsInode for Fat32Inode {
    fn read_at(&self, offset: usize, buf: &mut [u8]) -> usize {
        let fs = self.fs.exclusive_access();
        let mut file = fat32_open_file(&fs, &self.path)?;
        file.seek(SeekFrom::Start(offset as u64))?;
        file.read(buf).unwrap_or(0)
    }

    fn lookup(&self, name: &str) -> Option<Arc<dyn VfsInode>> {
        let fs = self.fs.exclusive_access();
        let dir = fat32_open_dir(&fs, &self.path)?;

        for entry in dir.iter() {
            if entry.file_name() == name {
                let kind = if entry.is_dir() {
                    VfsNodeKind::Dir
                } else {
                    VfsNodeKind::File
                };
                return Some(Arc::new(Fat32Inode::new(
                    fat32_path_join(&self.path, name),
                    kind,
                    self.fs.clone()
                )));
            }
        }
        None
    }
}
```

**设计思路**：
- 每次操作时临时打开文件/目录
- 不维护长期的文件描述符
- 通过路径字符串定位文件

## EXT4 实现

### 概述

使用 **lwext4_rust** 库（`vendor/lwext4_rust`），基于 C 语言的 lwext4 库。

**特点**：
- ✅ 完整的 ext2/ext3/ext4 支持
- ✅ 功能强大
- ⚠️ 依赖 C 库（需要交叉编译）
- ⚠️ 集成复杂度高

### 依赖配置

```toml
# os/Cargo.toml
lwext4_rust = {
    path = "../vendor/lwext4_rust",
    default-features = false,
    optional = true
}

[features]
ext4 = ["lwext4_rust"]  # 默认启用
```

**编译要求**：
- riscv64-linux-musl 交叉编译工具链
- CMake
- lwext4 C 源码（作为 git 子模块）

### 目录结构

```
os/src/fs/vfs/ext4/
├── disk.rs       # Ext4Disk: 块设备适配
├── fs.rs         # Ext4Fs: 文件系统管理
├── inode.rs      # Ext4Inode -> VfsInode 适配
└── mod.rs

vendor/lwext4_rust/
├── build.rs      # 构建脚本（编译 C 库）
├── c/lwext4/     # lwext4 C 源码（子模块）
└── src/
    ├── blockdev.rs   # Ext4BlockWrapper
    └── lib.rs
```

### 块设备适配

```rust
// os/src/fs/vfs/ext4/disk.rs

pub struct Ext4Disk {
    device: Arc<dyn BlockDevice>,
    cursor: UPSafeCell<Ext4Cursor>,  // 当前读写位置
    total_bytes: i64,
}

struct Ext4Cursor {
    block_id: usize,
    offset: usize,
}
```

**关键特性**：
- 维护当前游标位置（block_id + offset）
- 实现 `read_one`/`write_one`（块内读写）
- 支持 `seek` 操作（SEEK_SET/SEEK_CUR/SEEK_END）

**与 chronix 对齐**：
```rust
impl Ext4Disk {
    pub fn read_one(&self, buf: &mut [u8]) -> usize { ... }
    pub fn write_one(&self, buf: &[u8]) -> usize { ... }
    pub fn seek(&self, whence: i32, offset: i64) -> i64 { ... }
}
```

### 文件系统管理

```rust
// os/src/fs/vfs/ext4/fs.rs

pub(crate) struct Ext4Fs {
    _inner: UPSafeCell<Ext4BlockWrapper<Ext4Disk>>,
}

impl Ext4Fs {
    pub fn new(device: Arc<dyn BlockDevice>, total_bytes: i64)
        -> Result<Self, i32>
    {
        let wrapper = Ext4BlockWrapper::<Ext4Disk>::new_with_mount(
            Ext4Disk::new(device, total_bytes),
            "/",           // mount_point
            "ext4_fs0",    // device_name
        )?;

        Ok(Self {
            _inner: unsafe { UPSafeCell::new(wrapper) },
        })
    }
}
```

### VFS 适配

```rust
// os/src/fs/vfs/ext4/inode.rs

pub struct Ext4Inode {
    path: String,
    kind: VfsNodeKind,
}

impl VfsInode for Ext4Inode {
    fn read_at(&self, offset: usize, buf: &mut [u8]) -> usize {
        ext4_file_read(&self.path, offset, buf).unwrap_or(0)
    }

    fn lookup(&self, name: &str) -> Option<Arc<dyn VfsInode>> {
        let full_path = ext4_path_join(&self.path, name);

        if ext4_inode_exists(&full_path) {
            let kind = if ext4_is_dir(&full_path) {
                VfsNodeKind::Dir
            } else {
                VfsNodeKind::File
            };
            Some(Arc::new(Ext4Inode::new(full_path, kind)))
        } else {
            None
        }
    }
}
```

**设计特点**：
- 直接通过路径操作，不维护文件描述符
- lwext4_rust 内部管理所有的 C 状态

### 自动检测机制

```rust
// os/src/fs/vfs/mount.rs

#[cfg(feature = "ext4")]
fn probe_ext4_size() -> Option<i64> {
    let mut buf = [0u8; 1024];

    // 读取超级块（从块 2 开始）
    BLOCK_DEVICE.read_block(2, &mut block);
    buf[..512].copy_from_slice(&block);
    BLOCK_DEVICE.read_block(3, &mut block);
    buf[512..].copy_from_slice(&block);

    // 检查魔数
    let magic = u16::from_le_bytes([buf[0x38], buf[0x39]]);
    if magic != 0xEF53 {  // ext2/3/4 魔数
        return None;
    }

    // 解析文件系统大小
    let blocks_lo = u32::from_le_bytes([...]) as u64;
    let blocks_hi = u32::from_le_bytes([...]) as u64;
    let blocks = blocks_lo | (blocks_hi << 32);
    let log_block_size = u32::from_le_bytes([...]);
    let block_size = 1024u64 << log_block_size;

    Some((blocks * block_size) as i64)
}
```

## 已知问题

### 1. FAT32 相关问题 (已记录)

**文档**：`docs/GRLDocs/fat32_vfs_调试报告.md`

#### 问题 1: mkdir/chdir 失败
- **现象**：`sys_mkdirat` 仍走 ext4 的 `ext4_dir_mk`
- **原因**：系统调用层硬编码，未使用 VFS 抽象
- **状态**：⚠️ 需要修复

#### 问题 2: pipe 测试 panic
- **现象**：`wait(NULL)` 触发空指针写入
- **原因**：`sys_waitpid` 未处理 `NULL` 的合法场景
- **状态**：⚠️ 需要修复

### 2. EXT4 相关问题 (已记录)

**文档**：`docs/GRLDocs/ext4-adaptation-report.md`, `ext4-debug-report-fork-hang.md`

#### 问题 1: initproc not found
- **现象**：启动时找不到 init 程序
- **原因**：ext4 镜像内容为空
- **状态**：✅ 已解决（镜像已包含程序）

#### 问题 2: fork 卡住
- **现象**：fork 后子进程卡住
- **原因**：VFS 在 fork 时的同步问题
- **状态**：⚠️ 需要调查

#### 问题 3: C 库依赖
- **现象**：链接时缺少 libc 符号
- **原因**：lwext4 调试输出依赖 printf/fflush
- **状态**：✅ 已解决（关闭调试输出）

### 3. VFS 通用问题

#### 问题 1: 系统调用未完全 VFS 化
- **现象**：部分系统调用仍硬编码使用特定文件系统
- **影响**：切换根文件系统时功能异常
- **示例**：
  - `sys_mkdirat` → 直接调用 `ext4_dir_mk`
  - `sys_linkat` → 直接调用 ext4 API
- **状态**：⚠️ 需要重构

#### 问题 2: Dentry 缓存未启用
- **现象**：每次操作都需要重新查找
- **影响**：性能较差
- **状态**：💡 可优化

#### 问题 3: 缺少统一的错误处理
- **现象**：不同文件系统返回不同类型的错误
- **影响**：错误处理不一致
- **状态**：💡 可优化

## 技术细节

### VFS 路径解析流程

```rust
用户调用: open("/musl/busybox")
    │
    ├─> normalize_path("/musl/busybox")  // "/musl/busybox"
    │
    ├─> resolve_mount("/musl/busybox")   // 找到根挂载点
    │     └─> (mount="/", rel="musl/busybox")
    │
    ├─> root.lookup("musl")              // 查找 musl 目录
    │     └─> Some(musl_inode)
    │
    └─> musl_inode.lookup("busybox")     // 查找 busybox 文件
          └─> Some(busybox_inode)
```

```

    ├─> Fat32Disk::read_sector()

main()
  │
  ├─> drivers::init()              // 初始化块设备
  │     └─> VirtIOBlock::new()
  │
  ├─> fs::init()
  │     │
  │     ├─> if mount_ext4_auto() {  // 尝试 EXT4
  │     │     probe_ext4_size()      // 检测超级块
  │     │     Ext4Fs::new()          // 创建 ext4 实例
  │     │     mount_root_ext4()      // 挂载为根
  │     │   }
  │     │
  │     ├─> else if mount_fat32_auto() {  // 尝试 FAT32
  │     │     Fat32Fs::new()
  │     │     mount_root()
  │     │   }
  │     │
  │     └─> else {                   // Fallback to EasyFS
  │           mount_easyfs()
  │         }
  │
  └─> task::init()                   // 启动 init 进程
```

## 开发建议

### 添加新文件系统

如果要添加新的文件系统（如 NTFS, Btrfs），需要：

1. **创建适配目录**：
   ```
   os/src/fs/vfs/ntfs/
   ├── disk.rs     # 块设备适配
   ├── fs.rs       # 文件系统管理
   ├── inode.rs    # VfsInode 实现
   └── mod.rs
   ```

2. **实现 VfsInode trait**：
   ```rust
   pub struct NtfsInode { ... }

   impl VfsInode for NtfsInode {
       fn kind(&self) -> VfsNodeKind { ... }
       fn read_at(&self, offset: usize, buf: &mut [u8]) -> usize { ... }
       // ... 实现所有必需方法
   }
   ```

3. **添加挂载函数**：
   ```rust
   // os/src/fs/vfs/mount.rs
   pub fn mount_ntfs() -> Result<(), i32> {
       let root = ntfs_root()?;
       ROOT_VFS.exclusive_access().mount_root(root);
       Ok(())
   }
   ```

4. **更新 Cargo.toml**：
   ```toml
   [dependencies]
   ntfs_lib = { ... }

   [features]
   ntfs = ["ntfs_lib"]
   ```

### 调试技巧

1. **查看挂载的文件系统**：
   - 检查启动日志中的 "mounted ... as root"
   - 使用 `list_apps()` 查看根目录内容

2. **调试文件操作**：
   - 启用 trace 日志：`LOG=TRACE make run`
   - 查看 "vfs: resolve" 日志

3. **检查块设备**：
   - 使用 hexdump 查看镜像文件：
     ```bash
     hexdump -C sdcard-final.img | head -50
     ```
   - 检查超级块魔数
