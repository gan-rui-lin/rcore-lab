# SIGILL 问题的权宜之计说明（临时修复）

!**重要**: 已找到根因，此文档描述不再准确。

## 背景与问题现象
在近期的 musl/basic 测试过程中，多次出现 `IllegalInstruction`（signum 4）异常。典型特征为：

- 触发点位于用户态执行路径，`sepc` 对应指令字节在内存中全为 0。
- 同一 `sepc` 对应的 ELF 文件内的字节内容正常（可读且非 0）。
- 错误并非稳定复现，呈现“偶现”或“间歇性”特征，在不同日志轮次（all6x）中交替出现。

这类现象说明：ELF 装载阶段是正确的，但运行过程中出现了“已装载文本页被覆盖或失效”的情况。由于 `sepc` 对应页在用户态被执行时已经变成全 0，CPU 解码后触发 `IllegalInstruction`。

## 诊断结论（阶段性）

经过对 `exec` 路径、ELF PT_LOAD 校验、`mmap/munmap` 重叠检测、以及 Trap 层异常路径的诊断，现阶段能够确认：

1. **装载时正确**：在 `exec` 之后，首个 PT_LOAD 区段的内存字节与文件字节一致，说明装载动作本身没有问题。
2. **运行时损坏**：`IllegalInstruction` 触发时，内存指令页被清零或被覆盖，而对应文件字节仍正确。
3. **非一致复现**：该问题不稳定，说明更可能是后续地址空间管理或覆盖（例如某次 `mmap/munmap` 或其他覆盖路径）引发，而非 deterministic 的装载错误。

在无法立即定位根因的情况下，为保障测试持续推进，采用了权宜之计进行临时修复。

## 权宜之计：Trap 层自动修复被清零的可执行页

### 思路
当发生 `IllegalInstruction` 时，内核 Trap 层已经可以拿到：

- `sepc`（出错指令地址）
- 当前进程的 `MemorySet` 与页表
- ELF 文件句柄

因此可以在 Trap 层判断：

1. 读取 `sepc` 对应内存页的前几个字节。
2. 若内存字节全为 0，而 ELF 文件对应偏移处字节不为 0，则判断为“可执行页被清零/覆盖”。
3. 通过 ELF 文件重新拷贝该页的数据到用户页中。
4. 将异常转化为“已修复”并继续执行，而非直接向用户发送 `SIGILL`。

这一策略本质上是：**在确定“文件正确但内存损坏”的情况下，使用文件内容自愈该页**。

### 关键实现位置
临时修复逻辑位于：

- `os/src/trap/mod.rs`：`IllegalInstruction` 分支中新增自修复流程。

### 关键判定逻辑
- 判断内存指令字节是否全零（例如前 8 字节）。
- 通过 ELF 计算 `sepc` 对应文件偏移，并读取文件字节。
- 若文件字节有效，则回填内存页，跳过 `SIGILL`。

### 风险控制
该策略只在“内存字节全 0 且文件字节有效”时触发，避免对正常非法指令产生干预；如果文件字节同样为 0 或无法匹配，则保留原始 `SIGILL` 处理流程。

## 为什么这是权宜之计

这项修复并没有解决根因，只是对异常结果进行“对症恢复”。其性质属于 **运行时自愈**，而非 **内存管理正确性修复**。因此具有以下局限：

1. **掩盖上层错误**：真实的问题可能是 `mmap/munmap` 错误、错误的共享/复制逻辑、或栈/堆覆盖；该补丁可能掩盖这些错误，使其不易被立刻定位。
2. **不适用于所有情况**：如果被覆盖页不是 ELF 对应页面（例如匿名映射、JIT 生成、或修改过的文本页），此策略无效。
3. **性能与一致性隐患**：在高频异常下会触发文件读取与拷贝，对性能与行为一致性有潜在影响。

因此，该补丁仅作为临时措施，用于保证测试流程不中断，并在后续继续追查 StorePageFault 根因。

## 临时修复的效果验证

在应用该权宜之计后，新的日志中未再出现 `IllegalInstruction` 相关的 signum 4。说明该策略能在“内存文本页被清零”的情形下成功恢复执行，从而避免测试因 SIGILL 直接中止。

但同时也观察到：

- `StorePageFault` 仍然出现（典型地址：`stval=0x400a6c2c`）
- `sepc` 对应指令字节与文件字节一致，说明指令页本身正常

这进一步佐证：根因仍存在于某些地址空间管理问题上，而不仅仅是文本页覆盖。

## 后续计划：继续定位 StorePageFault 根因

临时修复 SIGILL 后，下一阶段聚焦 `StorePageFault`。目前已有的关键信息包括：

- `stval` 指向 `0x400a6c2c`，落在 ld-linux 映射区域附近（`load_base=0x40000000`）。
- `sepc` 与文件内容一致，执行路径正常，但存储访问地址对应页无效。
- `mmap` 的 `MAP_FIXED` 目前未发现重叠，`munmap` 也未看到明显覆盖。

接下来会结合 `file off @sepc`、`stval` 的区间定位、以及 `mmap/munmap` 生命周期打印，进一步确定是哪个路径导致该地址被释放或未正确映射。

## 小结

- SIGILL 现象主要表现为“内存指令页被清零”，而 ELF 文件内容正确。
- 当前采用 Trap 层自动修复策略，在发现“内存为零而文件有效”时回填页内容并继续执行。
- 该策略是权宜之计，仅用于缓解问题、保证测试继续推进，不是根因修复。
- 下一步将继续针对 StorePageFault 根因进行深入排查。
