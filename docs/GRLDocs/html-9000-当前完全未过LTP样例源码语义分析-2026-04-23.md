## 2. 结论先行

如果只从“源码投入产出比”看，**当前完全未过** 且 **值得优先改** 的方向，不是 `all` 最高的那几个，而是下面这些：

1. **`preadv/preadv2` 家族**
   - 合计 `all = 138`
   - 语义非常集中：本质上是“定位向量读 + iovec/offset/error path 校验”
   - 现有内核已经有 `readv/writev/pread64/pwritev`，缺的是 `preadv/preadv2`
   - 这一类最像“补一条 syscall + 复用现有 user memory / iovec 逻辑”，性价比最高

2. **`sched_*` 调度参数/策略校验家族**
   - 合计 `all = 134`
   - 以 errno 与参数合法性检查为主
   - 现有 `sched_setscheduler` 在源码里还是 stub，修复空间明确
   - 这是“分不少、实现深度又不算离谱”的第二优先级

3. **`sethostname/setdomainname/utsname` UTS 语义家族**
   - 合计 `all = 104`
   - 主要测主机名/域名设置、可见性与传播语义
   - `uname()` 已有，实现面相对收敛
   - 如果短期不打算做 namespace，全量不一定都拿下，但基础分比较值得做

4. **`syslog11/syslog12` 内核日志接口**
   - 合计 `all = 23`
   - 分数不算最高，但代码现状最“明显错误”，属于快修型收益
   - 现在 `sys_syslog()` 基本只是碰一下用户缓冲区，不按 `type/len/权限` 走真实语义

5. **`shmat/shmget` 的 SysV SHM 基础语义**
   - 合计 `all = 26`
   - 已有实现，不是“从零开始”
   - 更像 attach 地址选择、权限与特定 flag 语义不完整
   - 属于中等投入但比较稳的补分点

6. **`mlock` 基础语义**
   - 合计 `all = 34`
   - 语义相对集中：成功锁页、`ENOMEM`、`EPERM`
   - 如果短期想补一条独立 syscall，这一类也不错

相反，虽然分很高，但**暂时不建议优先**的方向是：

1. **`name_to_handle_at/open_by_handle_at`**
   - 合计 `all = 232`
   - 分数极高，但这是 VFS 的“文件句柄导出/按句柄重开”能力
   - 要补 mount id、opaque handle、stale handle、`CAP_DAC_READ_SEARCH` 等语义
   - 工程量和复杂度都明显高于表面分数

2. **`personality01`**
   - 合计 `all = 72`
   - 测的是进程 personality/exec domain
   - 分看上去高，但对当前内核整体能力收益不大，优先级偏低

3. **`clone301/kcmp/setns/unshare/mq_open` 一类高级进程/namespace/消息队列接口**
   - 多数不是“基础 syscall 补一补”就能过
   - 会牵涉 pidfd、namespace、POSIX mqueue、跨进程对象比较等高级语义

## 3. 当前高分完全未过样例：按真实测试语义分类

### 3.1 高分但不建议优先：文件句柄导出 / 句柄重开

**代表样例**

- `name_to_handle_at01`：合计 `all = 112`
- `name_to_handle_at02`：合计 `all = 36`
- `open_by_handle_at01`：合计 `all = 52`
- `open_by_handle_at02`：合计 `all = 32`
- 家族总计：`232`

**LTP 实际在测什么**

- `name_to_handle_at01.c`
  - 基本语义：把 pathname 转成 `file_handle + mount_id`
  - 然后再配合 `open_by_handle_at()` 打开并 `fstat()`
  - 覆盖 `AT_EMPTY_PATH`、`AT_SYMLINK_FOLLOW`、不同 open flags
- `name_to_handle_at02.c`
  - 主要是错误语义：`EBADF / ENOTDIR / EFAULT / EOVERFLOW / EINVAL / ENOENT`
- `open_by_handle_at01.c`
  - 基本语义：使用 handle 重新打开文件/目录，并验证 `fstat()`
- `open_by_handle_at02.c`
  - 主要是错误语义：`EBADF / ESTALE / EFAULT / EINVAL / EPERM / ELOOP`

**当前源码状态**

- 在 `os/src/syscall/mod.rs` 里只能看到 syscall 名字映射，看不到对应实现入口
- `os/src/syscall/` 下也没有 `sys_name_to_handle_at()` / `sys_open_by_handle_at()` 实现

**价值判断**

- **不建议优先**
- 原因不是分低，而是语义过深：
  - 需要稳定的 mount id
  - 需要可持久化/可验证的 file handle 表示
  - 需要 stale handle 语义
  - 需要 capability 检查
  - 需要和现有 VFS inode/path 解析深度绑定

---

### 3.2 推荐优先：定位向量读与 bad-user-pointer/error-path 校验

**代表样例**

- `preadv02`：合计 `all = 32`
- `preadv02_64`：合计 `all = 32`
- `preadv01`：合计 `all = 12`
- `preadv01_64`：合计 `all = 12`
- `preadv202`：合计 `all = 25`
- `preadv202_64`：合计 `all = 25`
- 家族总计：`138`

**LTP 实际在测什么**

- `preadv02.c`
  - 重点是错误路径：
  - `EINVAL`：非法 `iov_len` / `iovcnt < 0` / `offset < 0`
  - `EFAULT`：坏用户地址
  - `EBADF`：无效 fd / fd 不可读
  - `EISDIR`：目录 fd
  - `ESPIPE`：管道 fd
- `preadv202.c`
  - 在 `preadv2` 上继续测：
  - 非法 flag -> `EOPNOTSUPP`
  - 其它 bad address / bad fd / pipe / directory error path

**当前源码状态**

- 已有：
  - `sys_readv()`：`os/src/syscall/fs.rs`
  - `sys_writev()`：`os/src/syscall/fs.rs`
  - `sys_pread64()`：`os/src/syscall/fs.rs`
  - `sys_pwritev()`：`os/src/syscall/fs.rs`
- 但 `sys_preadv()` / `sys_preadv2()` 没有看到实现与调度入口
- `os/src/syscall/mod.rs` 里仅有 `"preadv"` 名字，没有对应 dispatch

**价值判断**

- **强烈建议优先**
- 原因：
  - 语义集中
  - 内核已有大部分可复用基础件
  - 触点主要在 `fs.rs` 与 user buffer/iovec 校验逻辑
  - 一旦补齐，常常能顺带提升 `readv/pwritev` 同类边界语义一致性

**建议触点**

- `os/src/syscall/fs.rs`
- `os/src/syscall/user_mem.rs`

### 3.3 推荐优先：调度策略/参数校验与返回值语义

**代表样例**

- `sched_setscheduler01`：合计 `all = 29`
- `sched_setparam03`：合计 `all = 15`
- `sched_rr_get_interval03`：合计 `all = 16`
- `sched_rr_get_interval01`：合计 `all = 12`
- `sched_setparam01/02/04/05`：各 `8`
- `sched_getscheduler02`：`8`
- `sched_setaffinity01`：`7`
- 家族总计：`134`

**LTP 实际在测什么**

- `sched_setscheduler01.c`
  - 主要测错误语义：
  - 无效 pid -> `ESRCH`
  - 无效 policy -> `EINVAL`
  - 坏 `param` 指针 -> `EFAULT`
  - 非法 priority -> `EINVAL`
- 这类家族总体上主要是：
  - pid 校验
  - policy 校验
  - `sched_param` 读写与范围检查
  - RR 时间片返回
  - 基础 affinity 参数合法性

**当前源码状态**

- `sys_sched_setscheduler()` 在 `os/src/syscall/process.rs` 里是 stub：
  - 直接 `return 0`
- `sys_sched_getscheduler()` / `sys_sched_getparam()` 也只是最简语义

**价值判断**

- **建议优先**
- 原因：
  - 分数大
  - 多数是参数校验与 errno 语义，不要求复杂调度器改造
  - 很适合“先把 stub 改成正确失败路径/最小成功路径”

### 3.4 推荐优先：UTS 主机名/域名设置与可见性语义

**代表样例**

- `sethostname02`：合计 `all = 24`
- `setdomainname02`：合计 `all = 24`
- `sethostname03`：合计 `all = 14`
- `setdomainname03`：合计 `all = 14`
- `sethostname01`：合计 `all = 8`
- `setdomainname01`：合计 `all = 8`
- `utsname02`：合计 `all = 12`
- 家族总计：`104`

**LTP 实际在测什么**

- `setdomainname02.c`
  - 长度非法 -> `EINVAL`
  - 长度超限 -> `EINVAL`
  - `name == NULL` -> `EFAULT`
- `setdomainname.h`
  - 通过 `TEST_SETHOSTNAME` 宏复用同一套逻辑去测 `sethostname*`
  - 也就是 `sethostname02/03/...` 本质上与 `setdomainname` 同一家族
- `utsname02.c`
  - 两个普通进程共享同一个 UTS 状态
  - 第一个子进程改 hostname
  - 第二个子进程应能看到同样变化

**当前源码状态**

- `uname()` 已有实现：`os/src/syscall/process.rs`
- 但没有看到 `sys_sethostname()` / `sys_setdomainname()` 实现入口

**价值判断**

- **建议优先**
- 原因：
  - 和现有 `uname()` 能力接得上
  - 不做 namespace 时，至少可以先拿下“单 namespace 全局 UTS 状态”这部分
  - `utsname02` 这种 case 本质上也是在验证“普通进程共享同一份 UTS 状态”

**补充说明**

- `setns02` / `unshare01` 也涉及 UTS / mount / IPC namespace，但那是下一层复杂度
- 如果当前目标只是补分，不建议一开始就跳到 namespace 语义

### 3.5 快修型推荐：`syslog11/syslog12` 内核日志接口

**代表样例**

- `syslog12`：合计 `all = 19`
- `syslog11`：合计 `all = 4`
- 家族总计：`23`

**LTP 实际在测什么**

- `syslog12.c`
  - 非法 `type` -> `EINVAL`
  - `NULL` buffer -> `EINVAL`
  - 负长度 -> `EINVAL`
  - console level 越界 -> `EINVAL`
  - 非 root -> `EPERM`
- `syslog11.c`
  - type `0..8` 的基础成功语义

**当前源码状态**

- `sys_syslog()` 已有，但实现非常简化：
  - `len == 0` 直接返回 `0`
  - `buf == NULL` 返回 `EFAULT`
  - 否则只往用户缓冲区写 1 个字节后返回 `0`
- 位置：`os/src/syscall/process.rs`

**价值判断**

- **建议优先**
- 原因：
  - 当前实现与 LTP 期望语义明显不匹配
  - 这类 case 主要是 command/type 校验与权限判断
  - 修起来通常不需要大改调度/VFS/内存管理

## 5. 对后续修复顺序的具体建议

如果目标是 **“尽快从完全未过里拿到更多 TPASS”**，建议按下面顺序推进：

1. **先补 `preadv`，再顺手带 `preadv2`**
   - 原因：与现有 `readv/pread64/pwritev` 复用度最高
   - 很适合先做 bad-address / bad-fd / bad-offset / bad-iovcnt 这些错误路径

2. **把 `sched_setscheduler` 从 stub 改成真实校验**
   - 至少先把 `ESRCH / EINVAL / EFAULT` 这些最基础的 errno 做对
   - 这一步通常就能回收不少 case

3. **补 `sethostname/setdomainname` 的基础 syscall**
   - 不做 namespace 也能先拿下大量基础 UTS case
   - 再考虑 `utsname02` 这种“普通进程共享 UTS 状态”的传播验证

4. **把 `sys_syslog` 从“写一个字节就返回”改成真实 type 分发**
   - `syslog12` 很适合当快修目标

5. **继续打磨 SysV SHM**
   - 已有 `shmget/shmat` 实现，比从零补新 syscall 更稳

## 6. 一句话判断

如果只看 **分数**，最显眼的是 `name_to_handle_at/open_by_handle_at`；  
如果看 **源码现实与投入产出比**，最值得优先改的是：

- `preadv/preadv2`
- `sched_*`
- `sethostname/setdomainname/utsname`
- `syslog`

这四类更像“现有内核框架上补真实语义”，而不是“另起一整套高级子系统”。
