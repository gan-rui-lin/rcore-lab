lwext4_rust 库依赖 musl 交叉编译器，要额外下载 riscv64-linux-musl 工具链并配置环境变量
为了避免拉取增加编译时间，请使用 vendor/ 下的本地依赖（例如 os/Cargo.toml 里用 ../vendor/riscv 和 ../vendor/virtio-drivers），不要用 git 远程依赖。

TRACE_PID=1 LOG=TRACE SINGLE_TEST=/musl/basic/getpid bash run.sh -f sdcard-rv.img -t debug  命令输出 TRACE 级别的 LOG，并且运行单个测试点 /musl/basic/getpid；输出里面有包含个参数和返回值的 syscall trace(针对 trace_pid)

LOG=TRACE SINGLE_TEST=/musl/basic/getpid bash run.sh -f sdcard-rv.img -t all 会比 debug 模式更快地运行单测，并且无任何日志打印。

可以仔细研究一下 run.sh，大致和之前项目使用方式一致：脚本会先触发 `make debug`（或对应的 build 目标）构建内核和用户程序，再根据 `-f` 指定的镜像文件启动 QEMU，最后把日志等级和单测开关透传给构建/运行过程。

单测的“只跑一个测试点”是通过 `SINGLE_TEST` 环境变量控制的，它会在编译用户态 `user/src/bin/initcode.rs` 时被内联进二进制（`option_env!("SINGLE_TEST")`）。在 `initcode.rs` 里，`main()` 会优先检查 `SINGLE_TEST`，如果设置了就只执行 `run_single_binary(path)`，否则走常规的测试脚本集合（如 basic/libc/ltp 等）。也就是说，`SINGLE_TEST=/musl/basic/getpid` 会直接 `fork + execve` 运行该二进制，完全绕开批量脚本。

如果只想看某个进程的 syscall trace，可以设置 `TRACE_PID`（编译期注入）：比如 `TRACE_PID=1 LOG=TRACE ...`，只有 pid=1 的 syscall 会输出 trace。

按 PID：TRACE_PID=1 LOG=TRACE SINGLE_TEST=/musl/basic/getpid bash run.sh -f sdcard-rv.img -t debug
按名字：TRACE_NAME=getpid LOG=TRACE SINGLE_TEST=/musl/basic/getpid bash run.sh -f sdcard-rv.img -t debug（会匹配 exec 后的 basename，比如 busybox、getpid）
