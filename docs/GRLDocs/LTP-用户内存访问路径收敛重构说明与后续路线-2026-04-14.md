# LTP 用户内存访问路径收敛重构说明与后续路线（2026-04-14）

## 1. 背景与问题陈述

近期 LTP 调试中，多个问题都指向同一类根因：

1. 用户缓冲区访问逻辑分散在 `fs/process/net/ipc/task` 等多个子系统。
2. 同一种操作（内核读用户内存 / 内核写用户内存）在不同函数里有不同校验策略。
3. lazy page / demand fault / COW fault 触发与处理路径不统一，容易出现“某个 syscall 修了、另一个 syscall 又踩坑”。
4. 为兼容历史用例（例如部分 fork 场景）而存在的“宽松写入”行为散落在各处，后续维护风险高。

这会直接导致：

- 新增或修复 syscall 时容易遗漏某一类地址访问语义。
- 一处行为调整（例如 COW 写策略）很难保证全局一致。
- LTP 失败分析成本高，协作者需要在大量重复逻辑中反复比对。

本轮重构目标是先做**工程收敛**：把“用户内存访问 + 懒分配/COW处理策略”收口到尽可能少、可审计的入口函数中，再逐步演进到更强类型化方案。

## 3. 设计目标与非目标

### 3.1 目标

1. 将 syscall 层“访问用户内存”的策略尽量统一到一个模块。
2. 明确区分读写语义：
   - 读：`StrictChecked` 与 `DemandPaged`
   - 写：`StrictChecked` / `DemandCowWithForkFallback` / `RelaxedReadableMapping`
3. 保留已有行为兼容（尤其是历史 fork 相关用例），在不破坏通过率的前提下收敛代码路径。
4. 为后续对齐参考仓库（typed user ptr / vm ensure_access）铺路。

### 3.2 非目标

1. 本轮不做 mm 架构级重写（不引入全新 `UserVmSpace` API）。
2. 不在本轮彻底删除所有 legacy fallback（避免回归）。
3. 不改变 trap 层页故障主处理流程。

---

## 4. 核心重构内容

## 4.1 新增统一入口模块：`os/src/syscall/user_mem.rs`

该模块成为 syscall 层访问用户内存的单点入口，核心能力如下：

1. 策略枚举：
   - `UserReadPolicy::{StrictChecked, DemandPaged}`
   - `UserWritePolicy::{StrictChecked, DemandCowWithForkFallback, RelaxedReadableMapping}`
2. 统一缓冲翻译：
   - `translated_user_read_buffer()`
   - `translated_user_write_buffer()`
3. 统一拷贝工具：
   - `copy_to_user()`
   - `copy_from_user()`
   - `read_from_user<T>()`
4. 统一“仅校验可访问性”入口：
   - `ensure_user_readable()`
   - `ensure_user_writable()`
5. 统一 fault 触发：
   - `try_resolve_user_readable()`：读场景 demand fault
   - `try_resolve_user_cow_writable()`：写场景 demand + COW
6. 兼容 fallback：
   - `legacy_fork_write_fallback()`：保留 fork 历史行为（受进程名限制）。

### 动机

- 过去是每个子系统都手写“翻译+循环拷贝+EFAULT判断+可能触发fault”。
- 现在策略先枚举化，再映射到统一函数，行为可审计、可复用、可逐步收紧。

---

## 4.2 `process` 收敛：futex + capget + 通用拷贝

1. 本地 `copy_to_user/read_from_user` 改为调用 `user_mem`。
2. `sys_futex` 原先手工 `handle_demand_fault` 逻辑替换为：
   - `ensure_user_readable(..., DemandPaged)`
3. `sys_capget` 的用户输出缓冲写入可达性检测改为：
   - `ensure_user_writable(..., DemandCowWithForkFallback)`

### 收益

- futex 与其他 syscall 一样，走统一 demand read 入口，避免单点逻辑漂移。
- capget 不再手工分叉“translated_check + is_user_range_writable”，语义更一致。

---

## 4.3 `ipc` 收敛：`msgsnd/msgrcv`

`sys_msgsnd/sys_msgrcv` 由手写多段 buffer 拷贝改为统一 helper：

1. `msgsnd`：
   - `mtype` 使用 `read_from_user::<isize>(DemandPaged)`
   - `mtext` 使用 `copy_from_user(DemandPaged)`
2. `msgrcv`：
   - `mtype/mtext` 输出使用 `copy_to_user(DemandCowWithForkFallback)`

### 收益

- IPC 消息读写不再维护独立拷贝循环。
- 对 demand/COW 的行为与 fs/net/process 对齐。

---

## 4.4 `fs` 收敛：高频路径批量替换

本轮已收敛以下路径到统一 helper：

1. `sys_readlinkat` 输出缓冲写入 -> `copy_to_user`
2. `sys_getrandom` 写缓冲翻译 -> `translated_user_write_buffer(DemandCowWithForkFallback)`
3. `read_times_from_user` -> `copy_from_user(DemandPaged)`
4. `read_itimerspec_from_user/write_itimerspec_to_user` -> `copy_from_user/copy_to_user`
5. `read_user_bytes` -> `copy_from_user`
6. `fcntl(F_GETLK/F_SETLK)` 可读写检查 -> `ensure_user_readable/ensure_user_writable`
7. `readv/writev/pwritev` iovec 元数据读取 -> `copy_from_user`
8. 若干读缓冲输入路径 -> `translated_user_read_buffer`

### 收益

- `fs.rs` 中最容易复制粘贴出错的“16字节 iovec 解析 + 多段拷贝”已明显减少。
- 与 `process/net/ipc` 保持相同的错误语义与 fault 触发语义。

---

## 4.5 `net` 收敛：sockaddr / recvfrom / getsockopt

1. `read_sockaddr/read_sockaddr_for_connect/read_sockaddr_family/read_unix_sockaddr`
   - 统一改为 `copy_from_user`
2. `recvfrom` 数据回写
   - 统一使用 `copy_to_user`
3. `getsockopt` 多处分支写回 `optval`
   - 统一使用 `copy_to_user`
4. `socketpair` 参数可读检查
   - 统一 `ensure_user_readable`

### 收益

- 网络路径过去大量 `translated_byte_buffer + unsafe dst copy`，现在主路径都走统一 helper。
- 可读性、审计性和一致性都明显提高。

---

## 4.6 `task` 层补强（非 syscall，但属于用户缓冲边界）

1. `task/mod.rs::copy_to_user`
   - 从 `translated_byte_buffer` 改为 `translated_byte_buffer_checked(..., true)`
2. `task/process.rs` 的 exec 调试读取入口内存
   - 从 unchecked 翻译改为 checked 翻译（失败时保留默认 debug bytes）

### 收益

- 即使非 syscall 路径，也不再默认放宽用户地址翻译。
- 与“统一可达性检查”理念一致。

---

## 5. 重构前后对比（工程视角）

### 重构前

- 每个子系统各写一套：
  - 用户指针合法性判断
  - 页级遍历
  - buffer 分段 copy
  - EFAULT 处理
  - demand/COW 触发逻辑（有些地方有，有些地方没有）

### 重构后

- 大部分 syscall 路径统一为：
  1. 选择策略（Read/Write + strict/demand/relaxed）
  2. 调用 `user_mem` helper
  3. 业务逻辑仅关心数据与返回值

这个变化把“行为正确性”从业务函数下沉到统一安全函数中，协作者 review 时可以集中关注 `user_mem.rs` 与策略选择是否合理。

---

## 6. 与参考仓库对照（oskernel2025-chronix-retest）

参考仓库的关键点：

1. `mm/page_table.rs::translate_uva_checked(...)`
2. `mm/user.rs::UserPtrRaw/UserSliceRaw::ensure_read/ensure_write`
3. `mm/vm/uvm.rs::ensure_access(...)`
4. syscall 层普遍使用 `ensure_read/ensure_write`，而不是直接做页表翻译细节。

### 已对齐点（本仓库）

1. “统一入口”思想已落地：`syscall/user_mem.rs`。
2. 业务层不再大量手写 `translated_byte_buffer*` 循环。
3. demand/COW 触发已集中到单模块。

### 尚未完全对齐点

1. **分层位置仍在 syscall 层**：
   - 目前入口在 `syscall/user_mem.rs`，参考实现更偏向 `mm/user.rs + vm.ensure_access`。
2. **类型系统能力弱于参考实现**：
   - 目前以函数 + policy 为主，尚未达到 `UserSlice<T, ReadMark/WriteMark>` 的权限类型约束。
3. **fallback 仍存在**：
   - `legacy_fork_write_fallback()` 仍是兼容行为，不是长期形态。
4. **锁模型与生命周期表达较弱**：
   - 当前仍返回 `Vec<&'static mut [u8]>` 风格，后续建议演进为更受控的 borrow/guard 语义。

---

## 7. 后续迭代路线（建议按优先级）

## P0（优先）

1. 将 `syscall/user_mem.rs` 逐步下沉到 `mm`（例如 `mm/user_access.rs`）。
2. 对外只暴露稳定 API：
   - `ensure_readable/ensure_writable`
   - `copy_from_user/copy_to_user`
3. 禁止新代码直接调用 `translated_byte_buffer*`（通过 code review 规则执行）。

**验收标准**：`syscall/net/fs/process/ipc/task` 不再出现业务层直连 `translated_byte_buffer*`。

## P1（中优先）

1. 引入 typed wrapper：
   - `UserPtrRaw<T>`, `UserSliceRaw<T>`
   - `ReadMark/WriteMark`
2. 将“权限正确性”从运行时检查进一步转为编译期约束。

**验收标准**：常见 syscall 入参通过 `ensure_read/ensure_write` 获得 typed handle，再做业务读写。

## P2（兼容清理）

1. 评估并收缩 `legacy_fork_write_fallback()`：
   - 建议加入统计/日志开关，量化触发频率。
2. 分阶段替换为更严格策略。

**验收标准**：fallback 触发逐步归零，LTP 通过率不回退。

## P3（测试体系）

1. 建立“用户内存访问语义测试组”：
   - lazy read/write
   - COW write
   - PROT_NONE/RO/invalid pointer
   - 跨页、页边界、零长度
2. 在 CI 增加快速回归集。

**验收标准**：每次相关改动都能在固定测试集中稳定复现/回归。

## 10. 安全函数手册（本次重构新增/收敛重点）

本节给协作者一个可以直接落地的“API 使用规范”。

统一入口文件：`os/src/syscall/user_mem.rs`

### 10.1 策略枚举

`UserReadPolicy`：

1. `StrictChecked`
2. `DemandPaged`

`UserWritePolicy`：

1. `StrictChecked`
2. `DemandCowWithForkFallback`
3. `RelaxedReadableMapping`

策略选择建议：

1. 普通“读用户输入参数”优先 `DemandPaged`（避免 lazy 映射误判 EFAULT）。
2. 普通“向用户写结果”优先 `DemandCowWithForkFallback`（兼容 COW 与历史 fork 场景）。
3. 仅在确有历史兼容需求时才用 `RelaxedReadableMapping`（例如少数旧行为保留点）。
4. 网络/协议字段这种强校验场景可用 `StrictChecked`。

### 10.2 核心安全函数说明

### `copy_from_user(token, src, dst, policy) -> Result<(), isize>`

用途：从用户地址读入内核缓冲。

推荐场景：

1. 读取固定大小结构（sockaddr、iovec、timespec 等）。
2. 读取变长消息体（IPC mtext、net payload）。
3. 替代手写 `translated_byte_buffer_checked + for` 拷贝循环。

使用示例：

```rust
let mut raw = [0u8; 16];
user_mem::copy_from_user(token, addr_ptr, &mut raw, UserReadPolicy::DemandPaged)
    .map_err(|_| errno(EFAULT))?;
```

### `copy_to_user(token, dst, data, policy) -> Result<(), isize>`

用途：将内核数据写回用户地址。

推荐场景：

1. syscall 输出结构体/标量。
2. recv/read 等返回数据路径。
3. getsockopt/timerfd 这类“写用户缓冲 + 更新长度”的路径。

使用示例：

```rust
user_mem::copy_to_user(
    token,
    user_ptr,
    &val.to_ne_bytes(),
    UserWritePolicy::DemandCowWithForkFallback,
).map_err(|_| errno(EFAULT))?;
```

### `read_from_user::<T>(token, src, policy) -> Result<T, isize>`

用途：读取一个 `Copy` 类型的用户值。

推荐场景：

1. 读取 `isize/u32/TimeSpec` 等标量或小结构。
2. futex/cap/signal 等 syscall 的小参数读取。

使用示例：

```rust
let mtype = user_mem::read_from_user::<isize>(
    token,
    msgp as *const isize,
    UserReadPolicy::DemandPaged,
).map_err(|_| errno(EFAULT))?;
```

### `ensure_user_readable(token, ptr, len, policy) -> bool`

用途：只做“可读可达性”确认，不拷贝数据。

推荐场景：

1. 先验参数检查（例如 futex 地址预检）。
2. 不需要马上读取全部内容，但要提前给出 `EFAULT`。

使用示例：

```rust
if !user_mem::ensure_user_readable(token, uaddr as *const u8, 4, UserReadPolicy::DemandPaged) {
    return errno(EFAULT);
}
```

### `ensure_user_writable(token, ptr, len, policy) -> bool`

用途：只做“可写可达性”确认，不执行写入。

推荐场景：

1. 复杂分支前先判断输出缓冲可写。
2. 需要先决条件校验，再分阶段写入时。

使用示例：

```rust
if !user_mem::ensure_user_writable(
    token,
    data_ptr,
    data_len,
    UserWritePolicy::DemandCowWithForkFallback,
) {
    return errno(EFAULT);
}
```

### `translated_user_read_buffer / translated_user_write_buffer`

用途：返回页分段切片，供 `UserBuffer::new(...)` 等接口直接消费。

推荐场景：

1. 现有接口要求 `Vec<&mut [u8]>`（例如 `write_user_buffer`）。
2. 需要零额外复制地把用户缓冲透传给 VFS/设备层。

注意事项：

1. 除“兼容旧接口”外，优先使用 `copy_from_user/copy_to_user`。
2. 避免在业务层重新实现一遍分段 copy 循环。

### 10.3 典型场景与函数选型速查

1. 读取单个标量参数：`read_from_user::<T>(..., DemandPaged)`
2. 读取固定长度结构：`copy_from_user(..., DemandPaged)`
3. 写回单个标量：`copy_to_user(..., DemandCowWithForkFallback)`
4. 写回变长数据：`copy_to_user(..., DemandCowWithForkFallback)`
5. 仅做读可达性探测：`ensure_user_readable(...)`
6. 仅做写可达性探测：`ensure_user_writable(...)`
7. 接口必须拿分段切片：`translated_user_*_buffer(...)`

### 10.4 反模式（建议在 review 中直接拒绝）

1. 在业务函数里新写 `translated_byte_buffer_checked + for` 拷贝循环。
2. 手工调用 `handle_demand_fault/handle_cow_fault`（应通过 `user_mem` 间接触发）。
3. 同一函数内混用多个风格的用户访问逻辑（导致错误语义漂移）。
4. 无理由使用 `RelaxedReadableMapping`（会放宽语义，应限量使用）。

### 10.5 推荐模板（给后续新增 syscall 使用）

读取用户输入：

```rust
let mut in_buf = vec![0u8; len];
user_mem::copy_from_user(token, user_ptr, in_buf.as_mut_slice(), UserReadPolicy::DemandPaged)
    .map_err(|_| errno(EFAULT))?;
```

写回用户输出：

```rust
user_mem::copy_to_user(
    token,
    user_out,
    out_bytes,
    UserWritePolicy::DemandCowWithForkFallback,
).map_err(|_| errno(EFAULT))?;
```

只做预检查：

```rust
if !user_mem::ensure_user_readable(token, ptr, len, UserReadPolicy::DemandPaged) {
    return errno(EFAULT);
}
```
