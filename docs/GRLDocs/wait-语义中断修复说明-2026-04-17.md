# wait 语义中断修复说明（2026-04-17）

## 1. 背景

在 LTP 长跑（尤其是 glibc-ltp 套件）中，出现过“单测可过、套件偶发卡住”的现象，典型卡点集中在 `waitid09/10/11` 附近。症状是：

- 用例进入后没有继续推进到后续 case。
- 外层执行流长时间停留在等待路径。
- 单独执行 `waitid11` 通常可通过，说明并非简单的功能缺失。

本次文档聚焦内核 `wait` 语义侧修复，不讨论脚本超时包装策略。

## 2. 根因（一句话）

`sys_waitid/sys_waitpid` 在阻塞等待后缺少对“应中断的未屏蔽信号”的正确判定，导致等待循环在部分信号场景下不能及时以 `EINTR` 退出，从而在套件长跑中表现为偶发卡住。

## 3. 调查路径与证据

### 3.1 代码定位

主要检查点在 `os/src/syscall/process.rs`：

- `has_unmasked_user_signal_without_restart()`
- `sys_waitid(...)`
- `sys_waitpid(...)`

### 3.2 语义差异（修复前后）

修复前的核心问题可以概括为：

1. 等待循环能挂起/唤醒，但“何时返回 `EINTR`”判定过窄。
2. 对 `SIG_DFL` 路径没有区分“默认忽略信号”和“默认非忽略信号”。
3. 结果是某些 pending 信号不会触发 wait 循环退出，形成等待路径停滞。

### 3.3 已执行的验证命令（会话内）

1. 单测回归：

```bash
SINGLE_TEST=/glibc/ltp/testcases/bin/waitid11 bash run.sh
```

2. 小窗口套件验证（从 `waitid09` 开始，限制 case 数）：

```bash
LOG=WARN SINGLE_TEST=glibc-ltp LTP_START_FROM=waitid09 LTP_CASE_LIMIT=3 timeout 600 bash run.sh
```

观察结果：`waitid09/10/11` 能连续完成并继续推进到后续 case（不再停在 `waitid11`）。

## 4. 修复内容

### 4.1 新的中断判定辅助函数

在 `has_unmasked_user_signal_without_restart()` 中，按 Linux 语义细化判定：

1. `SIG_IGN`：不打断 wait。
2. `SIG_DFL`：
   - 若属于默认忽略信号（如 `SIGCHLD` 等）则不打断。
   - 若属于默认非忽略信号，则允许打断 wait。
3. 用户自定义 handler：
   - 设置了 `SA_RESTART` 则不打断。
   - 未设置 `SA_RESTART` 则打断，返回 `EINTR`。

### 4.2 wait 系统调用接入点

在 `sys_waitid` 与 `sys_waitpid` 的阻塞路径中，`suspend_current_and_run_next()` 返回后统一调用上述判定；满足条件时返回 `errno(EINTR)`，而不是继续无限等待。

## 5. 为什么这能有效避免卡住

核心机制是把“阻塞等待”变成“可被正确中断的阻塞等待”。

在长跑环境里，信号到达时序更复杂（含定时器、父子进程事件、并发 wakeup 等）。如果 wait 循环没有正确处理中断条件，就可能一直重新进入等待，表现为卡住。修复后：

1. pending 且未屏蔽、并且语义上应打断的信号，会让 wait 路径及时返回 `EINTR`。
2. 用户态可以按 libc/LTP 预期执行重试或错误分支，流程继续推进。
3. 默认忽略信号不会误触发中断，减少“假阳性 EINTR”。

## 6. 与 Linux 语义对齐点

本次对齐的重点不是“所有信号行为一次到位”，而是 wait 中断语义的关键决策顺序：

1. 先看是否有可报告子进程事件（退出/停止/继续）。
2. 无事件且为阻塞等待时，再检查信号中断条件。
3. 仅在应中断时返回 `EINTR`。
4. `SIG_DFL` 与 `SA_RESTART` 参与判定，不再把所有默认动作一刀切忽略。

## 7. 残余风险与边界

1. 极端并发下，`wait` 与信号投递时序仍可能暴露新的角落行为。
2. 目前主要验证了 `waitid` 相关窗口，仍需更大范围回归覆盖。
3. 默认忽略信号集合目前以实测问题为导向，后续可继续与 Linux 信号表逐项核对。

## 8. 后续改进点

1. **统一阻塞语义框架**：把 `wait/futex/nanosleep/poll` 的 `EINTR + SA_RESTART` 判定抽象成同一套内核辅助逻辑，减少分叉行为。
2. **补齐一致性回归**：新增一组“信号到达时序 + 阻塞 syscall”组合测试，覆盖 `SIGALRM/SIGCHLD/SIGUSR1` 与 `SA_RESTART` 开关矩阵。
3. **增强可观测性**：在 debug 级别增加 wait 中断原因日志（信号号、action、mask、是否 restart），便于快速定位偶发卡住。
4. **扩展套件验证**：在通过小窗口后，固定批次执行更长的 glibc-ltp 区间回归，持续观察是否存在新的 RUN/FAIL 断裂点。
